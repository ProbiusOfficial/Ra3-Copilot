# 协议技能「需要该阵营基地」的门槛 —— 逆向记录

> 本文只写**实测 / 反汇编**得到的事实。推断一律标注「待验证」。
> 目标：跨阵营注入的协议技能，在没有该阵营基地时按钮是灰的、点不动；基地一出现立刻可用，拆掉立刻退回。
> 工具：`ra3-copilot` 的 HTTP 桥（`127.0.0.1:17832`）+ `research/tools/_pe.py` / `_dis2.py` / `_memfind.py` / `_live.py`。

## 一、这一轮新打通的逆向原语（可直接复用）

### 1. 名字 intern（把 C 字符串变成引擎 nameKey）

```
buf  = GET /sbuf?s=SpecialPowerModule          → 回地址（DLL 自有 128 字节缓冲，不碰游戏堆）
nk   = POST /aicall?fn=0x98ACB0&this=[0xD07338]&a0=<buf>&na=1
```

实测：`SpecialPowerModule` → `nk=0x056F`；`ProductionUpdate` → `0x0564`；`Behavior` → `0x0881`。
（`[0xD07338]` 是 intern 表的 `this`，当前值 `0x032BC030`。）

### 2. 模块枚举 —— `findModule` 的真实形态

反汇编 `0x6DD950`：

```asm
mov esi, [ecx+0x310]      ; ecx = Thing；[Thing+0x310] = 0 结尾的模块指针数组
.loop:
  ecx = [esi]
  if (!ecx) return 0
  vt = [ecx]; call [vt+0x10]   ; → 该模块的类型 nameKey
  if (eax == 目标key) return [esi]
  esi += 4 ; goto .loop
```

所以 **`[Thing+0x310]` = `Module*[]`（0 结尾）**，不是 vector。之前记的「模块向量」说法不准确。

现成配方（实测可用）：

```
nk  = intern("ProductionUpdate")
mod = POST /aicall?fn=0x6DD950&this=<Thing>&a0=<nk>&na=1
```

`this` **必须是 Thing**（传 GameObject 会 AV，实测 `c0000005`）。

### 3. `0x4A6BE0` 不是「修正符专用」，是通用模板存储查表

```
tpl = POST /call?rva=0xA6BE0&cc=cdecl&a0=<storeHash>&a1=<名字哈希>&a2=0
```

- `storeHash = 0xC5E07887` → AttributeModifier 存储（旧结论不变）。
- `storeHash = 0x81D85EFA` → **SpecialPowerTemplate 存储**（新）。

实测校验：

| 名字 | 哈希 | 返回 |
|---|---|---|
| `SpecialPower_PackReplaceSelf` | `0x6710551A` | `0x0CF3E3D0`（与该模块 ModuleData+0x08 指向的模板**完全一致**） |
| `SpecialPowerTimeBombLvl1` | `0x38B0D5B2` | `0x0CF74020` |
| `SpecialPower_CryoSatelliteLvl1` | `0xC20BD550` | `0`（容器里不是这个拼写） |

`SpecialPowerTemplate` 布局（实测）：`+0x00` 虚表（`0x00C5B6F8`）｜`+0x20` = 名字哈希｜`+0x3C` = 小整数（疑为 SpecialPowerEnum，待验证）｜`+0x0C` = `0x31`。
⚠ 不同技能的 `+0x14`/`+0x18`/`+0x40` 值形态差异大（有的像指针、有的像哈希），**不能当成同构字段直接 diff**。

### 4. 全进程字符串扫描（找桥函数 / Lua 常量）

`research/tools/_memfind.py`：64 位 Python 用 `OpenProcess + VirtualQueryEx + ReadProcessMemory` 扫 32 位游戏进程，**不需要提权**。
用它确认了 `exPlayerTechUnlockBaseTechForPlayer` / `exPlayerTechChangeTechFaction` 只以**Lua 字节码字符串常量**形式存在于堆（`0x0699199C`、`0x079F7FF4`、`0x0516633C`、`0x06991A6C`），
**全 exe 与磁盘上的 DLL 里都没有可打印串** → `RA3LuaBridge.dll` 是加密/压缩的，静态拿不到桥函数体。

进程内已加载的模组模块（模块枚举：`TH32CS_SNAPMODULE32`）：


## 二、被否证的假设

### ① 「基地作为技能提供者」——**否证**

`AlliedConstructionYard`（`/summon?hash=0x61A093F6`）的 Thing 地址 `0x96175970`，
`[Thing+0x310]` 数组共 **54 个模块**，其中只有 2 个是 `SpecialPowerModule`
（`vt=0x00C27708` @`0x052A02A8` 与 `vt=0x00C45BE0` @`0x050CD050`），
它们引用的 SpecialPowerTemplate **都是 `SpecialPower_PackReplaceSelf`**（即基地车的打包/展开）。

⇒ 建造场**没有**用 `SpecialPowerModule` 给玩家提供任何协议技能。**「基地挂 provider 模块」这条不成立。**

### ② 「`Player+0xC4` / `+0xD4` 的显式禁用表」——仍**不是**灰态根因

当前（场上有盟军建造场）读 `Player+0xC4`：`begin == end`（长度 0）。灰态与这张表无关，与之前结论一致。

### ③ 「`0x686920` 是协议格前置判定」——**已作废**

`0x69A990` 用文件字节反汇编出来是垃圾（`push eax; add al,0x8b; …`），说明它**不是指令边界**。
基于它读出的 `call 0x686920` / `mov [esi+0x18],al` 全部无效；重扫 `E8 rel32` 指向 `0x686920` 的调用者为 **0 处**。
原文已归档（内部《作废-协议格前置判定》，未随仓库发布），「全协议」桩是否真的作用于面板格子**待重新验证**。

## 三、当前掌握的对象模型（实测地址 / 偏移）

| 对象 | 地址 / 偏移 | 说明 |
|---|---|---|
| 本地玩家 `Player` | `[[0xCE8C9C]+0x28]` = `0x02E891F0` | 与旧记录一致 |
| 玩家建筑列表 | `Player+0x1260` begin / `+0x1264` end | `Thing*` 数组；实测 `[0x89937710(伏龙殿), 0x96175970(盟军建造场)]` |
| 玩家其它容器 | `+0x1280`（vector，空）、`+0x1290` / `+0x12AC` / `+0x12C8`（自指入侵式链表，空）、`+0x12D8`（1 项） | 长度不随基地变化 |
| 技能禁用表 | `Player+0xC4` | `u32[]`，元素是 `sage_hash(小写技能名)`；`/power?state=Disabled` 会加一项 |
| SCPoint（协议点） | `[Player+0x1320]` | 旧地址 `0x0734B6C8` 会随对局变，**每次重新取** |
| PlayerTech 对象表 | `[[0xCE8DA8],[0xCE8DAC])`，81 项 | 名字哈希在 `obj+0x38`；实测 `0x1195EC78` 的 `+0x38 = 0xDF0CB732` = `playertech_allied` |

### 技能按钮的「锁定」显示

- UI 绑定名：**`HCGUI:PlayerPowerLocked`**（字符串 `0x00C7D8F8`，`.rdata`）。
- 唯一引用：`0x00A7E9D3`（`push 0x00C7D8F8`），位于 `0xA7E9C0` —— 某 UI 模板数据类的构造函数，它把该绑定名转成属性 id 存起来，并把虚表设成 `0x00C7D910`。
- `0x00C7D910` 虚表在**堆里 0 个实例**（全 exe 只有 1 处命中，就是那条 `mov [esi],0xC7D910` 指令本身）⇒ 这个子类在 1.12 构建里没被实例化（或者只是同名绑定被别的类复用）。
- 画按钮时调用链：
  ```asm
  A7E990  esi = [ecx+0x10]          ; 子对象
  A7E9A9  call 0xAD9EC0(esi+8)      ; ← 取「锁定」标志
  A7E9B2  je   → 不按锁定样式画
  A7E9B8  jmp 0xA7E930              ; 按锁定样式画
  ```
- `0xAD9EC0` = `return *(u8*)(*(u32*)(this+4) + 0x10)` —— **纯叶子 getter，读缓存字节**。
  它的调用者有 **90 处**，是通用「元素状态」getter，**不能整体 patch**（会影响一大片 UI）。

⇒ 结论：**「锁定」是一个被写进某对象的缓存字节，不是每帧现算**。真正要改的是写这个字节的那段逻辑，或者它上游的判定。

## 四、下一步（按性价比）

1. **给 `0xAD9EC0` 的 `this` 装一次轻量探针**：在 `0xA7E9AB` 处记录 `ecx`，连续几帧取样 → 拿到存活实例地址 → 顺着 `[[this+4]+0x10]` 读/写，验证「写 0 就亮」。
   （只写缓存字节，不动逻辑，可随时还原。）
2. **在写侧下断**：对那个字节下「写监视」（需要 hook `WriteProcessMemory` 不可行，改为在 4 个候选写点装 stub 记录调用栈）。
3. **回头补 `PlayerTech` 写入通道**：`RA3LuaBridge.dll` 是压缩的，静态拿不到；改为在进程里扫 `luaL_Reg` 形状的 `{name, func}` 表（名字在堆里已定位到 4 处），拿 func 指针。

## 五、破解（2026-10-19 17:5x 实测）

### 决定性实验链

1. 用截图拿到可编程判据：技能栏在**屏幕左侧一列**，亮态=高饱和彩色，灰态=灰阶。
2. 授予 `SpecialPowerTimeBombLvl1` + `SpecialPowerCryoSatelliteLvl1` → 第 3 格灰。
3. 召唤盟军建造场（`0x61A093F6`）→ **第 3 格立刻变彩色**（复现现象）。
4. 把建造场从 `Player+0x1260` 的建筑列表里摘掉（只把 `end` 从 `+8` 改成 `+4`，可还原）
   → **第 3 格立刻退回灰**。
   ⇒ **判定是每帧实时遍历 `Player+0x1260`，没有任何缓存字段。**
5. 把 `0x83B740`（遍历建筑列表的谓词函数）的失败分支改成恒真 → **列表里没有盟军基地，按钮也亮**。

### 判定函数：`0x83B740`

```asm
83B740  push ecx
83B741  eax = [ecx+0x1264]          ; Player 建筑列表 end
83B747  push ebp
83B748  ebp = [ecx+0x1260]          ; begin
83B760  esi = [ebp]                 ; Thing*
83B767  ecx = [esi+4]               ; ThingTemplate*
83B76B  call 0x7E43F0(tpl, arg1)    ; 模板是否满足过滤器
        ; 再按 arg2 指向的 4 个排除标志逐位过滤
83B81B  xor al,al / pop / ret 8     ; 未命中 → false
83B822  mov al,1  / pop / ret 8     ; 命中   → true
```

**解锁补丁**：`0x83B81B` 处 `32 C0`（`xor al,al`）→ `B0 01`（`mov al,1`），2 字节，等价于"该谓词恒真"。
同族还有三个，结构相同、失败分支的 `32 C0` 分别在：

| 函数 | 失败点 | 语义差异 |
|---|---|---|
| `0x83B740` | `0x83B81B` | `0x7E43F0(tpl, filter)` + 4 个排除标志 |
| `0x83B830` | `0x83B872` | `0x6FC510(thing, arg, 1)` + `0x4FAC10(this, thing, 0)` |
| `0x83B890` | `0x83B8D3` | 同上，但带 Player 参数 |
| `0x83EA10` | `0x83EA5F` | `ret 0x28`（10 个栈参），条件更复杂 |

实测 `0x83B740` 恒真即足以让跨阵营协议技能按钮点亮（此时玩家建筑列表里**没有**该阵营基地）。

### 副作用（待评估）

`0x83B740` 是通用的"玩家是否有满足条件的建筑"谓词，恒真会把**所有**依赖它的建筑前置检查一并放开
（建造菜单可能全解锁、超能武器可建等）。是否需要只放开"技能可用性"这一条调用路径，见下。

### 精确化的下一步

找出 `0x83B740` 的调用者中负责"技能可用性"的那一个，只 patch 那一个 call 点的返回值；
或对 `0x83B740` 的 4 个同族函数分别实测，取影响面最小的组合。

## 六、本轮踩到的两个坑（务必记住）

1. **`features.cpp` 的 `kHooks[].rva` 是 RVA（相对 `0x400000`），不是 VA。**
   写错成 VA 会让 `site = base + VA` 落到未映射地址，`VerifyBytes` 用裸 `memcmp` 读它 → AV 崩游戏。
   正确写法：`VA 0xA7E9AB` → `rva = 0x67E9AB`。
2. **`/poke` 原来写不了 `.text`**（页只读）。已改成走 `WriteRaw`（`VirtualProtect` + 写 + 还原），
   现在能改代码段。改完注意：**这些裸 patch 不在 hook 表里，卸载 DLL 不会自动还原**，重启游戏才复原。

## 七、落地（2026-10-19 17:5x）

裸 patch 已改为**受管功能项**，跟着 DLL 一起装卸、可反复开关、字节不符时不改动。

| 位置 | 内容 |
|---|---|
| `features.cpp` | `SetProtoUnlock(bool)` / `GetProtoUnlock()`：2 字节补丁，带 AOB 校验 + 幂等 |
| `httpapi.cpp` | `GET /unlock?on=0\|1`（不带 `on` 则取反） |
| `overlay.cpp` | 修改器面板「建造」页 -> 复选框 **「协议免基地前置」**（带悬停原理说明） |

常量：`kProtoUnlockRva = 0x43B81B`（= VA `0x83B81B` − `0x400000`），
`off = 32 C0`（`xor al,al`）/ `on = B0 01`（`mov al,1`）。

实测：`/unlock?on=1` → 字节 `B0 01`、按钮在**无该阵营基地**时仍为可释放态；
`/unlock?on=0` → 字节 `32 C0`、立刻退回灰。两端都返回 `ok`。

⚠ 仍然是"谓词恒真"，所以**同一谓词承担的建造前置判定也会一并放开**。
若日后发现建造菜单异常，再把补丁收窄到「技能可用性」那一条调用路径（见 §五末尾）。
