# 真实建造流程 —— 可行性方案

> 游戏侧机制、数据与地址见 `research/ai-build/README.md`
> 一句话：副官现用 `/summon` 裸创建成品建筑，跳过经济 / 时间 / 放置；本方案给出改走游戏正门的三条路径。

---

## 一、问题

`/summon` 走 `CreateUnit`（RVA `0x205240`）**直接造出成品建筑**，带来两个后果：

1. **脱离对局经济** —— 不扣钱、不耗时、无需落点，副官的建筑行为等于上帝模式，无法参与真实运营；
2. **对象不进玩家体系** —— `CreateUnit` 之后还须补 `0x84A0B0`（摘 pending）/ `0x838AB0`（激活）两步收尾，缺了则小地图图标空心、部分操作静默失效（详见 `docs/召唤单位状态字-根因与修复.md`）。

游戏自己的正门是另一条路 —— **建造场生产队列 + 落点组装**：

```
选中建造场 → 点建筑图标（立刻扣款 + 队列图标倒计时）
  → 倒计时结束，进入"待放置"
  → 在基地地面控制圈内点地面落点
       盟军：落点即组装成件
       苏联：落点后就地 buildup（从地面长起）
       帝国：Nanocore 移动到位后 unpack 展开
```

**RA3 没有 Dozer（施工车）单位**，`DozerAIUpdate` 一族是 SAGE 共用代码库的继承代码、未被实例化 —— 此点曾按 Generals 源码语义误判，已由对象表证伪，依据见 `research/ai-build/README.md`。

---

## 二、三条路径

| | A · 生产队列 | B · 模拟输入 | C · 纯对象创建（现状） |
|---|---|---|---|
| **做法** | 直调 `ProductionUpdate`（vtable `0x00C3F9A0`）的入队方法 → 玩家建造队列 | 选中建造场 → 点建筑按钮 → 点地面 | `CreateUnit` RVA `0x205240` + 后处理链 |
| **真实度** | 最高：扣款 / 计时 / 放置全走官方流程 | 与玩家操作完全同源 | 无：绕过一切 |
| **代价** | 入队方法**非虚函数**，须靠调用点定位；玩家侧 `ProductionUpdate` 实例的取得路径未定 | 需世界→屏幕投影 + 输入注入；`docs/MCP指挥作战-可行性调研.md` 的 P1 方案已论证、未实现 | 已实机可用 |
| **风险** | 低（走官方状态机） | 最低（不调任何游戏函数） | — |
| **限制** | 未知项最多 | 需游戏窗口前台；与玩家真实鼠标互斥 | 破坏经济与玩家体系一致性 |

---

## 三、推荐落地顺序

1. **B 先行** —— 复用 P1 模拟输入，一次覆盖建造、放置、技能、编队，且不碰引擎内部（避开状态机与"入世"风险）。
2. **A 再评估** —— 若需要后台无人值守建造（不依赖前台），再攻 `ProductionUpdate` 入队入口。
3. **`/summon` 保留为实验 / 救场通道**，从副官的常规决策里摘出去，避免再出现绕过官方管线的副作用。

---

## 四、未决问题

1. `ProductionUpdate` 入队方法（非虚）的地址，与玩家侧实例的取得路径 —— 路径 A 的唯一缺口。
2. 建筑对象 "construction percent" 字段的偏移（可由 `ADJUST_HEIGHT_BY_CONSTRUCTION_PERCENT` 所属模块反查）。
3. 副官侧的"建造意图 → 具体建筑 → 落点"决策：可直接借游戏 AI 的 `AIBuildStateDefinition`（按"阵营 + 建筑类型 + 场景"分类）与 `GetAIStructurePlacementLocation`（AI 落点计算）的思路 —— 见 `research/ai-build/README.md`。
