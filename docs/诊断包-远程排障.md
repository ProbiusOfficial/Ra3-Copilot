# 诊断包：把别人的现场搬回来

> 只在别人机器上出现的问题（自己这边正常），不用远程、不用猜。跑一次 `ra3diag.exe`，
> 生成一个文本文件，发回来就能离线判断。

## 一、什么时候用

- 战役目标面板显示「节点不存在」，但对方说目标确实该完成了
- 点了修复/完成，日志报成功，游戏里毫无反应
- 注入成功了，接口却不应答
- 同一个功能在别人那台机器上表现不一样

## 二、怎么跑

`ra3diag.exe` 是独立程序，**不依赖修改器是否注入**，自己读游戏内存 + 拉一遍接口。

1. 先进对局（要采脚本节点，必须在局内）
2. 双击 `ra3diag.exe`，UAC 弹窗点「是」（游戏是管理员权限运行，不提权读不到内存）
3. 等 10~30 秒，窗口关闭或在末尾停住
4. 与 exe 同目录生成 `ra3diag_20260101_120000.txt`

命令行可用参数：`ra3diag.exe <输出目录>`、`--noelev`（不提权）、`--nopause`（跑完不停）。

## 三、里面有什么

| 段 | 内容 | 能看出什么 |
|---|---|---|
| 头部 | 时间、是否管理员、依赖总数（取自内置表） | 提权失败的话内存段会空 |
| `[1]` | 游戏 pid、exe 路径/大小/时间、PE 时间戳/SizeOfImage/校验和 | 是不是适配的那份构建 |
| `[2]` | `ra3copilot.dll` 在不在、哪一份（路径/大小）、其它非系统模块 | 工具版本、以及 Mod / 汉化 / 启动器注入的 DLL |
| `[3]` | `/ping` `/state` `/objectives` `/flagdbg` `/enemy` `/log` 的**原文** | 接口是否活着、目标状态、模块自己的判断 |
| `[3]` 后半 | `/scripttbl`、`/scripttbl?dump=1`、`/scripttbl?t=timer&dump=1` | **脚本变量表本体**：`ready/engine/flagRoot/节点数/badParent/unsorted` + 两张表全部条目（scope / 名字哈希 / 原始值 / 真值）。
判「某个 flag 到底写过没有」直接看这里的 `dump` —— 表里没有就是从未写过，不必再猜 |
| `[4]` | 独立内存扫描：当前地图每个脚本依赖的**全部**候选，带树指针/作用域/值/页密度/区域类型，以及命中点原始字节 | 与模块的判断对照，看是"脚本没写过"还是"模块挑错了对象" |
| `[5]` | **关卡脚本解析**：读 `.big` 里的 `.map` 生成目标表，打印 `scripts/objs/paths` 与全部 `M|`/`O|` 行 | 目标表能不能生成 —— 不看修改器是否注入都能回答 |

## 三·五、怎么读 `[3]` 里的脚本变量表

```
ready=1                引擎指针读到了
engine=039A8B80        ScriptEngine 实例（每局会变，正常）
flagRoot=0781FA80      flag 表根；0 = 空表（还没进关）
flagCount=82           表里有 82 条 flag
badParent=0            父子互指全部正确
unsorted=0             中序键严格递增
```

`badParent` 与 `unsorted` **必须都是 0**。只要有一个非 0，就说明我们的偏移在这份 exe 上读偏了，
此时后面所有"节点不存在 / 值不对"的结论都不可信 —— 先怀疑工具，别怀疑玩家。

`dump` 段一行一条：`#节点地址 scope=作用域哈希 hash=名字哈希 raw=原始值 bool=真值`。

- `raw=94000F00` / `bool=0` → 这条 flag 存在且为假；
- 表里**找不到**这个名字哈希 → 本局脚本从未写过它（判定的那条 IF 从未成立）。

## 三·六、怎么读 `[5]` 关卡脚本解析

这一段完全不依赖修改器：程序自己按当前地图路径去 `.big` 里找 `.map`，解压、遍历脚本树、
按 `SET_MISSION_OBJECTIVE_STATUS(目标, 2)` / `MARK_MISSION_OBJECTIVE_COMPLETED(目标)`
生成目标表。**DLL 没注入、接口全无应答时，这一段照样输出**。

```
游戏目录: C://GAME//Red Alert 3\Data
地图路径: data\maps\official\CAMP_A01_BrightonBeach_Smith\CAMP_A01_BrightonBeach_Smith.map
map=camp_a01_brightonbeach_smith
来源=data\maps\official\camp_a01_brightonbeach_smith\camp_a01_brightonbeach_smith.map
scripts=397 objs=9 paths=11 lines=12
M|camp_a01_brightonbeach_smith
O|Objective 01 - Destroy Soviets|1|TTIMER - Objective Buffer|FFLAG - Intro Soviet 02 Patrol Destroyed
...
```

读法：

| 现象 | 判定 | 处置 |
|---|---|---|
| `scripts` 几百、`objs` ≥ 1、列出 `O|` 行 | 解析正常 | 目标表问题不在数据侧，回头查 `[3]`/`[4]` |
| `脚本里没有 SET_MISSION_OBJECTIVE_STATUS(...,2)` | 这关的完成动作是别的写法，或地图不是战役图 | 目标面板对这关确实没内容；不是 bug |
| `在 .big 与散文件里都没找到 xxx.map` | 游戏目录不对，或图在 mod 独立目录 | 看上面「游戏目录」是否指向游戏本体；mod 图需要额外路径 |
| `脚本树越界（格式不符）` / `名字池(CkMp)解析失败` | 这份 `.map` 不是 NWB 格式或版本不同 | 记下 `地图路径`，属于需要补适配的情形 |
| `拿不到当前地图路径` | 不在对局里 | 进关后重跑 |

**`来源=` 那行**是消歧用的：同一个地图名如果同时存在于散文件与 `.big`，这里会显示实际读的是哪一份
（散文件优先 —— 游戏文件系统就是这个顺序，mod 覆盖走这条）。

## 四、怎么读 `[4]`

每条依赖一行 `H=<哈希> <类型>[<名字>] c=<候选数>`，下面每个候选一行：

```
#05466F98 L=00000000 P=00000000 R=06062BA0 scope=9FA0497C hash=DE36FD03 val=BF382601 page_density=1 type=PRIVATE region=05466000
```

- `c=0` —— 内存里没有这个名字哈希。脚本从没 `SET` 过它（条件不成立），不是扫描漏了。
- `type=IMAGE` + `module=ra3copilot.dll` —— 命中的是修改器自己的哈希表，不是节点。
- `scope=00000000` / `val` 等于另一个 `H=` 的值 —— 数组错位读出来的假节点。
- `page_density` 远大于 1 —— 一片挨着一片，是数组不是节点。
- 真节点长这样：`type=PRIVATE`、`page_density=1`、`scope` 是 `811C9DC5`/`9FA0497C` 这类作用域哈希、`val` 是标志值。

## 五、注意

- 只读：`OpenProcess(PROCESS_VM_READ)`，不写目标进程、不改任何游戏文件。
- 内容只有进程路径、模块名、脚本节点与接口回执，不含账号或个人信息。
