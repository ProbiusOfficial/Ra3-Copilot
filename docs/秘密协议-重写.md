## 三、脚本栈（不是标准 Lua 5.1）

【实测】`/luatest` 四参数回读 `L=046D1B20 top=4 | a1=SELFTEST_1 … a4=SELFTEST_4 | type=4,4,4,4`

- `lua_State+0x00` = top、`+0x10` = base，槽 16 字节
- 槽：`{ tag@+0, pad@+4, value@+8, pad@+12 }`
- 【实测】`tag = 4` 且字符放在 `value+0xC` 的槽能被 `0x178670` 原样取回（四参数自检）
- 【反汇编】`0x178670` 取参数用只认 tag 4 的取值器（`0xA5D0`）
- tag `1` / `3` 的含义本局**没有验证过**（旧文档写的「1=nil、3=Lua串」无实测支撑）

## 四、`0x178670`（注册名 `ExecuteAction`）

【反汇编】注册代码在 `0x1B0788`：`push 0xC08D24`（"ExecuteAction"）+ `push 0x578670`（函数 VA）。

```asm
1786E1  call 0x104E10        ; 在 [0xCD8CE4]+0xBC 按名字查描述符
1786F5  mov ebx,[eax+4]      ; 描述符
17870A  call 0x327140        ; (输出缓冲, 描述符)
178723  call 0x40A980        ; lua_pushstring 压回
178735  mov eax,1 / ret      ; 返回 1 个结果
```

`0x327140` 内部：`push ebx / push edi / push eax / push ecx / push [esi+0xDC] / push 0xC3A860 / push 缓冲 / call 0x4CC5C0`
—— 参数排列与 `sprintf` 一致；已核对的指令里没有写游戏状态的语句。

【实测】从外部压栈调 `0x178670`，返回值为 1；调用前后玩家对象无变化（差分只剩帧计数器）。

## 六、协议点链路

【实测】本局逐级读回：

```
ctx     = [0xCE8C9C]
Player  = [ctx + 0x28]         = 0x032A31F0
SCPoint = [Player + 0x1320]    = 0x04DD4890
余额     = [SCPoint + 0x34]
```

【实测】写 `[SCPoint+0x34] = 15` 后读回 15；写 99 后读回 99（HUD 数字要等刷新）。

【反汇编】`0x4394D0` = 点数 setter：

```asm
eax = [ecx+0x38]        ; 上限；= -1 表示无上限
edx = [esp+4]           ; 新值
if (eax > 0 && [ecx+0x34] + edx > eax) [ecx+0x34] = eax
else                                    [ecx+0x34] = edx
```

（`0x4394D0` 在全 `.text` 里只有一个 `call`：`0x185E6F`，位于 `0x185E10` 那个函数内部。）

## 九、面板相关反汇编（只记指令，不记语义）

### 9.1 `0x69AB00` = 格控件 vtable `0xC7E00C` 的 slot 1

证据：【实测】`.rdata:0x87E010` 存着 `0x00A9AB00`，而 `0x87E010 = 0xC7E00C + 4`。

```asm
69AB03  mov eax,[esi+0x14]
69AB06  test eax,eax / je 0x69AB43
69AB0A  cmp byte [esi+0x18],0 / jne 0x69AB43
69AB13  edi = [[eax]+4]
69AB16  eax = [esi+4]
69AB19  edx = [eax+0x78]
69AB1C  ecx = eax+0x5C
69AB1F  eax = [ecx+0x18]            ; = [parent+0x74]
69AB26  线性查 [eax] == edi
69AB33  未找到 → 0x69AB43（直接返回）
69AB36  call 0x69A8F0(edi)
```

【实测】本局面板对象 `0x07509230`：`+0x18` = Player、`+0x70` = SCPoint、
`+0x20`…`+0x58` = 15 个格控件指针、`+0x74` = `0`、`+0x78` = `0`。

【实测】在 `0x69AB03` 挂钩后点击任意格，`tap` 计数恒为 `0`（一次也没进）。

### 9.2 `0x686920`

【实测】扫 `.text` 全部 `E8 rel32`，指向 `0x686920` 的只有 `0x69A9A2` 一处。
该处位于逐格刷新函数内（`0x69A990` 起）。

### 9.3 `0x68D890`（被 `0x69AAC1` 调用）

```asm
68D899  ecx = [Player+0x1320]        ; SCPoint
68D8A3  SCPoint 空 → return 1
68D8B0  esi = [[obj]+4]              ; id
68D8B4  call 0x43C320(SCPoint, id)
68D8BE  al != 0 → return 2
68D8CC  call 0x68D760(parent+0x5C, obj+4)
68D8E5  非零 → return 0
68D8EA  call 0x682170
68D8F1  零 → return 1，否则 return 0
```

### 9.4 `0x68D900`（返回值经 `0x69AAE9` 传给 `[esp+0x10]` 的 vtable `+0x1C`）

```asm
68D900  eax = [ecx+8]
68D903  test eax,eax / jg 0x68D90A
68D907  xor al,al / ret              ; eax <= 0 时返回 0
68D90A  edx = [ecx+4] → [edx+0x1C] → [edx]      ; 二维表
68D912  eax -= 1
68D915  cmp eax,[edx+8] / jge 0x68D933
68D919  esi = [ecx+0xC]
68D921  cmp esi,[edx+eax*8] / jge 0x68D933
68D929  取 [表] 里 [eax] 行的对象
68D933  对象为空 → 返回 0
68D937  ecx = [ecx+0x14]                       ; 本格 obj
68D941  push [本格 obj 的 id] / push [上一个 obj 的 id]
68D946  call 0x446500                          ; 返回值原样返回
```

`0x446500(a, b)`【反汇编】：`a` 当容器（`begin=+4`、`end=+8`），递归判断 `b` 是否在其中。

### 9.5 `0x6CFE95` 段

```asm
6CFE95  edi = [eax+0x1320]          ; SCPoint
6CFEA1  call 0x439500               ; (idx+1 >= total) ? 1 : 0
6CFEAC  call 0x43F570               ; 当前格需求
6CFEB5  movss xmm0,[edi+0x2C]       ; 进度
6CFEC2  cvtsi2ss / divss            ; 进度 / 需求
6CFEF0  clamp 到 [0,1]
```

`0x439500`：`eax=[ecx+0x28]→[eax+0x10]`；`ecx=[ecx+0x30]+1`；`cmp ecx,[eax+0xA8]`；`sbb;add`。
`0x43F570`：`ecx=[ecx+0x30]`；`if ecx >= [[Player+0x10]]+0xA8 return 0`；
`取 [[[Player+0x10]]+0xAC][ecx]`；空则 0；否则返回 `[[obj]+4]`。

【实测】本局 `[[Player+0x10]]+0xA8` = **10**；9 格的需求值均为 **360**。
