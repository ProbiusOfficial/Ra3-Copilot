# 血条常显 —— 机制与实现

> 目标：全图单位的血条一直画在头顶，不必选中、悬停或挨打才出现。
> 开关：局内菜单 → 杂项操作 → **血条常显**；HTTP `GET /hpbar?on=0|1`。

## 一、引擎怎么决定画不画

「这个 Drawable 要不要画血条」由一个判定函数回答。函数在二进制里存在**两份拷贝**
（一份 `this` 直接进 `ecx`，一份先从 `Drawable+0x138` 取到 Thing 再判），骨架一致：

```
cmp  byte [g_showBars], 0     ; 总开关，当前 = 1
je   → 返回 false
cmp  byte [g_uiGate],   0     ; 当前 = 0
jne  → 画血条分支              ← 只改这一字节
test byte [obj+0x13D], 0x40   ; 对象级「强制显示」位
jne  → 画血条分支
mov  eax, [obj+0x16C] / cmp eax, [g_cmp]   ; 之后再接一串对象级条件
```

`g_uiGate` 平时是 0，`jne` 永不成立，判定只能落到对象级条件上 —— 这就是默认只有
选中 / 悬停 / 刚挨打的单位有血条的原因。把 `jne`(75) 改成 `je`(74)，「`g_uiGate == 0`」
这一条反而变成「去画血条」，判定恒真。

**由此带来的行为**：判定不再区分对象，建筑、残骸、敌方单位一律显示。判定只回答
「画不画」，不决定血条数值，所以血量读数仍是引擎算好的真实值。

## 二、站点

| | 拷贝 A（jne +0x17） | 拷贝 B（jne +0x25） | `g_showBars` | `g_uiGate` |
|---|---|---|---|---|
| 零售 1.12 | RVA `0x12EB93` | RVA `0x11A4A0` | `0xCB0348` | `0xCDB725` |
| Steam 1.12 | RVA `0x170293` | RVA `0x15BCA0` | `0xCB4A10` | `0xCE08C5` |

两处必须同改 —— 只改一处会剩一半单位不显示。定位用 `constexpr` 双列 RVA + `Pick()`，
选列由 `buildinfo.h` 的 `SizeOfImage` 决议；构建认错时字节校验不过，一个字也不写。

跨构建稳定性已核对：`80 3D ?? ?? ?? ?? ?? 74 ?? 80 3D ?? ?? ?? ?? ?? 75 ?? F6 [81|85] 3D 01 00 00 40`
这条 AOB 在零售与 Steam 各唯一命中两处，与上表逐字节对应。

## 三、实现

`features.cpp` 的 `SetHealthBarAlways` / `GetHealthBarAlways`
（与 `SetProtoUnlock` 同一套写法）：

- 只写 **1 字节**，不动寄存器与栈 —— 与 hook 无关，没有 cave stub，卸不卸载 DLL 都无栈风险。
- 幂等：已是目标字节直接返回成功，重复勾选不会写坏。
- 失败即放弃：字节既不是 `75` 也不是 `74` 时返回 false 并报「字节不符，未改动」。
- 关闭时原样写回 `0x75`，判定立刻恢复原行为。

写内存走 `hook.h` 的 `WriteRaw`（内部自带页保护切换），因此 `.text` 也能直接改。

## 四、边界

- **与战网客户端冲突**：RA3 BattleNet 客户端的 `ShowHpBar` 就是这两个字节（日志里
  `patching hp bar` → `writing memory at 0x570293 / 0x55bca0 (1 bytes)`）。战网开着时
  我们这道开关本来就是「已开」态；**在这里关掉会把战网的也关掉**，重开游戏后战网
  会按自己的设置重新打上。
- **不持久化**：与免费建造、协议解锁一样，重注入 DLL 后回到关闭态，需要重新勾选。
- **卸载 DLL 不回写**：`RemoveHooks` 只负责 hook 站点，这两字节会留在 `0x74`。
  要还原用菜单取消勾选，或 `GET /hpbar?on=0`。
