# 无限缩放 —— 机制与实现

> 2026-10-17 交付。功能开关：`FID_ZOOM_IN`（`g_flags[0x0F]`）—— F8 热键 / 功能面板复选框 / `/toggle?f=15&on=1` 三路等价。
> 源码真相：`src/stubs.asm` 的 `ZoomCaveStub` / `ZoomEntryStub` 注释；本篇是机制与实测结论。

## 一、机制（字节级实证，非推断）

相机距离每帧在 `ra3_1.12.game+0x1EC7CD` 写入（VA `0x5EC7CD`），周边指令布局（静态反汇编 + live 内存双向核对，RVA == 文件偏移）：

```
0x5EC7C4: 38 5E 48                cmp byte ptr [esi+0x48], bl   ; ZF 由这条 cmp 定；原生态走 clamp 分支
0x5EC7C7: F3 0F 10 44 24 0C       movss xmm0, [esp+0xc]        ; 本轮计算出的目标距离
0x5EC7CD: F3 0F 11 46 44          movss [esi+0x44], xmm0       ; ← 5B hook 点
0x5EC7D2: 74 39                   je 0x5EC80D                  ; ← ZF=1 即跳过整段 clamp
0x5EC7D4..0x5EC806: vt[0]/vt[1] 取上下限 + call 0x4FDBD0        ; clamp 块
0x5EC809: D9 5E 44                fstp [esi+0x44]              ; clamp 结果写回
0x5EC80D: (je 目标) ...
```

**无限缩放的本质**：`0x1EC7D2` 的 `je` 只认 ZF。hook stub 末尾用 `cmp byte ptr [g_flags+0Fh], 1` 供标志：

- 开关开 → cmp 相等 → **ZF=1** → `je` 跳到 `0x5EC80D`，**整段 clamp（含 fstp 写回）被跳过** → `[esi+0x44]` 保留透传的原始计算值 → 滚轮每档 ×1.05 复利，无上限（实测数据见 §二 表）。
- 开关关 → `popfd` 还原 `0x5EC7C4` 那条 cmp 留下的自然 ZF → 与无 hook 原版**逐字节一致**（原生基线实测：拉远封顶 600.00，拉近 600→575→551→528）。

Stub 结构（`ZoomCaveStub`）：

```asm
pushad                          ; 通用寄存器
pushfd                          ; 保存自然 flags（0x5EC7C4 cmp 的 ZF）
movss dword ptr [esi+44h], xmm0 ; 原指令重放（5B）
...遥测（inc/mov，flags 反正会被重建）...
cmp   byte ptr [g_flags+0Fh], 1 ; 开 -> ZF=1
jne   zc_native
pop   eax                       ; 开 -> 丢弃自然 flags，保留 ZF=1（pop 不动 EFLAGS）
jmp   zc_out
zc_native:
popfd                           ; 关 -> 还原自然 flags
zc_out:
popad
jmp   dword ptr g_retZoom       ; 回 0x5EC7D2
```

⚠ 开态丢弃 flags 必须用 `pop eax`，**不能用 `add esp,4`**——add 会重建 EFLAGS 把 ZF 打回 0（静默失效）。
⚠ stub 内**绝不写 `fadd m32`**：上游 x87 栈已弹空，空栈 fadd 写 indefinite QNaN（`0xFFC00000`）并永久污染 `[esi+0x2730]`。
⚠ **绝不写 `[esi+0x34]`**：游戏按距离派生的相机系数（600↔1.7），外部硬写必和引擎约束打架（写 0.17 黑屏、写 17 贴脸）。
⚠ **不要回头写 `[this+0x2704]`（clamp 上限字段）**：clamp 跑不跑由上面的 ZF 决定，写字段治标不治本，且关闭态没有任何代码把它算回 600。废案全过程存档：`.workbuddy/memory/old/作废-无限缩放写上限方案.md`（私有库）。

## 二、血缘与关键实测

机制复刻自第三方 CE trainer 的 Ctrl+F8（2009 年产，脚本全表已从运行内存导出至 `research/tools/ce_scripts_dump.txt`，仅私有库）。其热键脚本只翻 `iEnable+0xF`/`+0x10` 两个标志字节 = **纯透传**；fadd/fsub 弹簧扰动是另一组旗标，热键从不产生。关键对照实验：

| 状态 | 行为 |
|---|---|
| 原生无 hook（干净基线） | 拉远封顶 600.00；拉近 600→575→551→527.96 |
| 参考实现 1/1（等效 Ctrl+F8） | 拉远 600→631→663→…→810 持续突破 |
| 本方 POC（直改运行中游戏） | 拉远 →1827，拉近正常回落 |
| 本方 DLL 开态（F8/HTTP 开） | 用户实机滚轮 → 1212.89，遥测 hits=73 |
| 本方 DLL 关态 | 1212.89 → 第一格即钳回 600，之后与原生基线逐格一致 |
