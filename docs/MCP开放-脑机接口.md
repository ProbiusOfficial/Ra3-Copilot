# MCP 开放（脑机接口）—— 让 AI 接入你的战局

> 2026-10-15 · `trainer-v2/` · 状态：**已实现并编译通过（BUILD_OK）；端点待重开游戏实测**
> 一句话：把修改器已有的进程内调试接口，用标准 **MCP 协议**开放给任意 AI —— AI 能看到你的部队和 AI 的部队，并能给你投放单位/箱子。

---

## 一、这是什么

在游戏内面板上多了一个 **「脑机接口」** 面板。打开它之后，任意支持 MCP 的 AI 客户端
（Claude Desktop、Cursor、各类 agent 框架…）就能：

| AI 能做什么 | 怎么做到 |
|---|---|
| **看局势** | 读取我方/敌方的**部队数、建筑数**、敌人阵营与兵种构成、资金、当前选中单位 |
| **查单位** | 1000+ 单位目录检索（中文名 / 拼音 / 英文模板名 / 哈希） |
| **加部队** | 召唤任意单位（暴兵、救场、空投支援） |
| **发奖励** | 空投治疗箱 / 现金箱 / 晋升箱 / 属性箱 |
| **动单位** | 对选中单位：复制 / 收编 / 摧毁 / 满级 / 调速 / 改血 |
| **改全局** | 电力无限 / 全科技 / 免费建造 / 去迷雾 / 无敌 / 秒杀 … 一整套开关 |

> **2026-10-16 更新：已取消「总闸」。** 接口只监听 `127.0.0.1`，单机环境下"把 MCP 配置交给 AI"
> 本身即视为授权；原先的开关只拦带 `ai=1` 的请求（徒增"到底开没开"的困惑），已移除。
> 现在的形态：**接口恒开放，AI 开箱即用**。完整接入说明见 [`AI接入指南.md`](AI接入指南.md)。

## 二、架构

```
┌──────────────────┐   MCP (stdio JSON-RPC)   ┌────────────────────┐
│ 任意 MCP 客户端    │ ◀──────────────────────▶ │ mcp/ra3_mcp.py     │
│ Claude/agent …    │                          │ （零依赖 Python）    │
└──────────────────┘                          └─────────┬──────────┘
                                                        │ HTTP 127.0.0.1:17832
                                              ┌─────────▼──────────┐
                                              │  ra3trainer.dll     │
                                              │  （游戏进程内）       │
                                              │  · 只读端点→HTTP线程  │
                                              │  · 变更端点→渲染线程  │
                                              └─────────┬──────────┘
                                                        │ 只读内存 / 调游戏函数
                                              ┌─────────▼──────────┐
                                              │ 红警3 日冕 mod       │
                                              └────────────────────┘
```

- **没有引入新进程依赖**：MCP 服务器就是个 Python 脚本，只连本机 HTTP 接口。
- **可执行单元（DLL）不变**：执行能力早就有了（18 个 HTTP 端点），这次只是**开了一扇标准门**。
- **感知能力是新增的**：全图单位枚举（见下）。

## 三、感知层的原理（★ 核心新增）

修改器原来只能读「游戏里选中的单位」。要回答"你有多少部队、AI 有多少部队"，必须**枚举全图对象**。

### 3.1 关键偏移（2026-10-15 现场逐条实测确认）

| 字段 | 位置 | 说明 |
|---|---|---|
| Thing vtable | `[Thing+0]` | 本构建 = `0x00C4DB60`（所有 Object 统一；运行时优先从选中单位推导） |
| **对象模板指针** | `[Thing+0x04]` | ★ 新发现 |
| **对象类型哈希** | `[模板+0x08]` | ★ 新发现（哈希 → 名字/阵营/类型） |
| **归属（owner）** | `[Thing+0x418]` | 指向 Team 对象（vtable 统一 `0x00C5BCE0`） |
| Team 索引 | `[Team+0x20]` | 实测 = 玩家 ID（本地玩家 = 2） |

> ⚠️ 真实单位是 **Drawable**（vtable `0x00BED890`），它的 `[+0x138]` 才是 **Thing**；
> 两者数据区相同但 **owner 只在 Thing 上**（`Drawable+0x418` = 0）。所以枚举扫 **Thing vtable**。

### 3.2 算法

```
扫本进程堆内存（MEM_PRIVATE 提交页，~2.1GB）→ 找所有 [addr]==ThingVtable
  → 对每个命中：读 owner=[T+0x418]、hash=[ [T+0x04] +0x08 ]
  → 用 battle_catalog（938 个"可玩对象"）过滤掉矿晶/树/弹道等场景物
  → 按 owner 分组：部队数 / 建筑数 / 阵营(多数派) / 种类 Top10
```

- **安全性**：纯只读、**不调任何游戏函数** → 在 HTTP 线程执行，与游戏主线程无竞态。
- **性能**：SSE2 加速扫描，一次约 **数百毫秒**；结果带 **3 秒缓存**（面板/HTTP 共用，不重复扫）。
- **版本适应性**：Thing vtable 优先从「当前选中单位 → `[d+0x138]`」动态推导，退化才用已知常量。

### 3.3 实测样例（2026-10-15，4 人局）

| 归属 | 部队 | 建筑 | 阵营 | 构成（节选） |
|---|---|---|---|---|
| **idx 2（本地玩家）** | 44 | 15 | 神州 | 迅雷天罡×15、蜂鸟侦查无人机×6、坦克杀手×5、揽星亭×5、伏龙殿×2 |
| idx 6 | 58 | 17 | 神州 | 破甲铁卫×25、凌波护卫战车×8、磁弩防空系统×4 |
| idx 5 | 43 | 15 | 盟军 | 标枪兵×22、冰冻直升机×5、光棱坦克×4 |
| idx 4 | 37 | 20 | 苏联 | 磁爆部队×10、恐怖机器人×7、战熊×4 |

## 六、怎么用

### 6.1 客户端配置

把这段贴进 MCP 客户端的配置（路径按你的实际位置）：

```json
{
  "mcpServers": {
    "ra3-copilot": {
      "command": "python",
      "args": ["C:\\Users\\admin\\WorkBuddy\\RA3\\trainer-v2\\mcp\\ra3_mcp.py"]
    }
  }
}
```

游戏内「脑机接口」面板里有一键复制的配置片段（路径由 DLL 自动填）。

### 6.2 游戏内操作

1. 进对局 → `INSERT` 开菜单；
2. 勾选主面板的 **「脑机接口」** → 弹出面板（**接口默认即开放，无需点任何开关**）；
3. 面板显示 **接口地址 / 已服务次数**、**我方与敌方部队数**（悬停敌行看兵种构成）与 **AI 调用记录**。

### 6.3 示例对话

> **你**：帮我看下现在局势。
> **AI**：`get_battle_state` → 你（神州）44 部队 15 建筑；三家里 idx6 神州最凶（58 部队，25 个破甲铁卫），idx5 盟军标枪兵海（22 个）。
> **你**：给前线空投两个治疗箱，再补 6 辆磁爆坦克。
> **AI**：`drop_crate("治疗", 2)` → 已空投；`search_units("磁爆")` → `summon_unit("磁爆坦克", 6)` → 已生成。

## 七、安全与已知风险

1. **无总闸（2026-10-16 起）**：接口恒开放。授权边界 = "你有没有把接口/MCP 交给这个 AI"；
   真正的隔离靠**只监听 127.0.0.1（单机）**——要收回就停掉注入 / 退出游戏。
2. **只读永远可用**：即使关闭，AI 也只能"看"——它读的是内存，写不了。
3. **调用可追溯**：所有 AI 变更调用进「输出记录」和面板的「AI 调用记录」，并计入放行/拒绝计数。
4. **扫描是只读**：全图枚举不调游戏函数、不改内存，最坏情况是读到脏值（已做指针/范围校验）。
5. **⚠️ 已知风险（承接既有）**：
   - **裸 `CreateUnit` 对步兵类不一定安全** —— 2026-10-15 实测召唤某些单位会崩（`C0000005`）。AI 大规模暴兵时建议**优先结构/载具类**；
   - 召唤出来的单位若"未入世"，后续对它操作会失败（已做 `ResolveThing` 判据）。
   - 说白了：**这是修改器，AI 拿着真枪**。想让 AI 稳健，先只在 L1（只读顾问）跑通再放权。

## 十、实机联调更新（2026-10-15 傍晚，第 2 轮）

### 10.1 新增：给**任意一方**召唤（`owner`）

原来 `/summon` **写死"归属 = 本地玩家"**，没法给 AI 加兵（做对照实验时很受限）。现已支持：

```bash
# 玩家索引见 /snapshot 的 owners[].idx / enemies[].idx（缺省或 0 = 你自己）
POST /summon?hash=0x703BAB39&count=5&owner=5
```

- DLL：`SummonByHashFor(hash, count, teamOverride, ...)`；`FindTeamByIdx(idx)` 用**缓存的全图枚举**把索引→队伍对象地址（只在 HTTP 线程执行）。
- MCP：`summon_unit(unit, count, owner)` —— 让 AI 能给对手"加兵"，或做侦测/对照实验。

### 10.2 实机踩坑与修正

| 发现 | 结论 / 处置 |
|---|---|
| **点「锁定金额/锁定血量」弹 ImGui 断言框**（`PopStyleColor() too many times`） | 根因是"按钮回调翻转了状态，而 Push/Pop 各判一次" → 已修，并加**帧末清栈护栏**（此类断言不可能再出现） |
| **战场枚举在"选中半初始化召唤物"时推错 vtable** → 态势显示全 0 | 已加校验 + 命中数兜底 |
| **召唤物小地图图标半透明 / 敌方不主动攻击它** | ⚠️ **未解决**。已排除：①交战补登记 ②6 个状态字 ③缺 `PostA/PostB` 创建后处理（当帧调与延迟 1.2s 调均无效）。**当前最佳解释 = 对象未能"完全入世"（对敌方不可见）** |
| `PostA/PostB`（`0x84A0B0`/`0x838AB0`）参数 | 已用**线性反汇编**钉死：thiscall `ecx=team`，栈参 `(0,obj)` / `(0,obj,0)`，`ret 8` / `ret 0xC`（**个数错一个就 esp 失衡必崩**）。**默认关闭**（未证明有用，且有"反复摘 pending 列表"的嫌疑） |

> 排查方法沉淀：`research/memscan/` 下有 `snap_objects.py`(全图枚举原型)、`samesame.py`(同型号 A/B)、
> `unit_state.py`(状态字统计)、`dis_postfn.py`/`dis_callsites.py`(对运行进程反汇编)——**都是只读的**。

### 10.3 ★ 定案：召唤物"隐形"的真正机制（2026-10-15 08:20）

**实验**（单 AI 干净局，变量隔离）：
1. 给我方召唤 1 个破军金甲 → 小地图图标半透明、**敌方不主动攻击**；
2. 用 `summon?owner=5` 给盟军召唤 1 只**警犬**（`AlliedScoutInfantry`，反隐单位）放到它旁边；
3. → **破军金甲图标立刻变实心**。

**结论**：召唤物出厂处于 **"隐形/未登记"** 状态。三个表现是一回事：

| 表现 | 原因 |
|---|---|
| 小地图图标半透明 | 游戏认为它所在位置"未探明" |
| 敌方不会主动攻击 | 对敌方而言它不可见 |
| 被反隐单位贴近后变实心 | 侦察单位把该区域"照亮"了 |

**技术表述**：对象**缺少"视野/迷雾贡献登记"**。正常建造路径必然包含这步；裸 `CreateUnit` 缺了它。
（玩家自己仍能选中/操作它 —— 本地客户端知道它存在。）

**已排除**（全部实测否掉）：① "交战会补登记" ② 6 个状态字 ③ 缺 `PostA/PostB` 创建后处理（当帧/延迟 1.2s 都无效） ④ 单纯"移动"触发。

**修法方向**：找到"把对象登记进视野/迷雾/分区系统"那一步（SAGE 常见于 `PartitionManager` / `ShroudManager` 的
`addObject`，或 Object 创建时的 reveal 初始化），在召唤后补调。

**实用现状**：这个"隐形"对玩家其实是**增益**（敌方无视你的召唤部队），不影响游玩；根因留作后续。

**副产品**：`/summon?owner=<索引>` 实机验证通过 —— 可以给任意一方（含 AI）召唤。

### 10.4 ★★★★★ 隐形根因定案 + 已修复（2026-10-15 08:27）

**方法**：同型号两种状态**逐字节对拍**（`research/memscan/diff_states.py`）——
场上同时有「被警犬照亮 = 实心」与「刚召唤 = 隐形」的破军金甲（同 vtable `0x00C4DB60`）。

**唯一的三处干净差异（全是 0 ↔ 非 0）**：

| 偏移 | 实心 | 隐形 |
|---|---|---|
| **+0xC8** | `0` | `0x800` |
| **+0x28** | `0` | `0x80000000` |
| **+0x208** | `0` | `0x80000000` |

**现场验证**：用 `/poke` 把隐形那个的三位清零 → 图标**立刻变实心**（探宝确认）✅

**根因 —— 是我们自己的补丁**：`SummonByHash` 里基于 CE 写下的
```cpp
[obj+0xC8] |= 0x800;     // 原注释："让对象进入世界"  ← 实际是把它【隐藏】
```
（`+0x28` / `+0x208` 是游戏自己在创建时置上的，我们没写过 → 必须主动清。）

这也解释了前面为什么 poke 那 6 个状态字没用 —— **漏了这三位**。

**修复（已落地 `actions.cpp`，BUILD_OK）**：
```cpp
[obj+0xC8]  &= ~0x800u;        // 原本是 |= 0x800 —— 改掉
[obj+0x28]  &= ~0x80000000u;
[obj+0x208] &= ~0x80000000u;
[obj+0xBC]  |=  0x80000000u;   // 保留：对拍时两边相同，与本症状无关
```

修复后：**召唤出来直接就是实心，敌方也会正常攻击它。**

> 注：本次"隐形"曾长期被当作**增益**（敌方无视召唤部队）；修掉之后这个"隐形外挂"也随之消失 ——
> 若将来想要，可用 `/poke` 再把那三位置回去。
