# 战役目标：自动识别 + 一键完成

> 用途：战役卡进度时，不必猜"哪个条件没满足"，直接列出本关所有目标、每条完成路径依赖哪些
> flag/计时器，点一下就把它们全拨到位 —— 脚本下一帧自己执行原有的 DO 块（打勾、挂后续计时器、
> 解除建筑无敌、推进剧情），**走的是脚本本来的判定路径，不是伪造进度**。

## 一、怎么用

修改器菜单（默认 `INSERT`，可在启动器里改）→ **杂项操作** → **战役目标（自动识别 · 一键完成）**

1. 点「扫描当前关卡」→ 等约 10 秒（后台线程，期间游戏可正常操作）
   —— 开头会先读当前关卡的 `.map` 生成目标表（几十毫秒），失败则沿用内置表
2. 顶部显示识别到的关卡名与脚本节点数
3. 每个目标可展开，列出所有完成路径；每条路径下列出每个依赖项及其当前状态
   （`满足` / `未满足` / `节点不存在`）
4. 点「完成这条路径」→ 把该路径的 flag/计时器全部拨到位

HTTP 等价接口：

```
GET  /objectives                 # 扫描 + 列出（文本，含每个依赖的当前状态）
                                 # 第二行 table=script|builtin 标明目标表来自关卡脚本还是内置表
POST /objdone?i=<目标序号>[&p=<路径序号>]   # 完成；省略 p 则自动选实体条件最少的一条
GET  /objdbg                     # 目标表解析结果（排查用）
GET  /flagdbg[?name=<名字>][&all=1]  # 某个依赖的**全部**内存候选（地址/树指针/作用域/值/区域类型）
POST /flag?name=<名字>&on=1|0    # 任意脚本 flag，按名字自动匹配作用域
```

### 实测：不真打也能推进剧情（A02 Cannes，2026-10-26）

盟军第二关 `Objective 02 - Send in Spies`（要 4 个码头各渗透一次），全程没派间谍，
直接从面板完成该目标的路径。证据不是"面板显示变了"，而是**脚本自己的 DO 块确实执行了**：

```
FLAG - Dock 01/03/05/07 Infiltrated   → 全 1   （我们写的，路径依赖）
FLAG - Objective 02 Complete          → 1      ← 我们没碰这条，是脚本 DO 块写的
```

同时 `LINK_MISSION_OBJECTIVE_TO_OBJECT`、改阵营关系、`ENABLE_SCRIPT Dialog - MA02_Spy*`
这些副作用一起发生，任务栏打勾、后续剧情正常往下走。

这就是走"脚本原本的判定路径"和"直接改任务状态"的区别 —— 后者只会让 UI 打个勾，
DO 块里的副作用全丢，剧情卡在原地。

**修复卡关**（杂项操作页，目标面板上方）：识别当前关卡后，把**第一个未完成目标**按它最省的一条
依赖路径拨到位 —— 与「完成这条路径」按钮同一套写入，脚本下一帧自己执行 DO 块。

- 只推进一个目标：一次全推会越过剧情，卡关要解的是当前这道坎。
- 目标表覆盖不到的图，回退为把地图自带的 `f_debug_skip_objective_01..04` 置 1。
- 查找放后台线程（一次全内存扫描约 10 秒，期间可正常操作），写回在渲染线程；
  回退路径的批量定位走 `ScriptFlagResolveBatch()`，不必为每个 flag 各扫一遍内存。

### 关卡识别：按地图文件

主判据是**当前地图路径**：`[0x00CD8CE4]`（TheGameLogic）`+0x98` 是 C 串，
实测形如 `data\maps\official\CAMP_S09_NewYork_Rao\CAMP_S09_NewYork_Rao.map`。
取 basename、去 `.map`、转小写后与目标表里的关卡名匹配，命中即用（`/objectives` 里显示 `score=9999`）。

这条读不到时才退回「脚本节点命中率」启发式 —— 那条**不可靠**：`TIMER - Objective Buffer`
几乎每张图都有，依赖项最多的 A01 曾经永远是最高分。因此面板保留了 **关卡下拉** 可以手动指定，
「修复关卡剧情异常」也吃同一个选择。


## 附：两张卡关图的脚本原文

目标完成条件在脚本里是 `orGroups` 的嵌套结构：组与组之间是**或**，同组内的条件之间是**与**。
调试器把每组展成一条「路径」，所以一条路径里既有 flag/timer，也可能有实体条件（记为 `other`）。

### 盟军第一关 `Objective 01 - Completed`

单组，三条同时成立：

```
TIMER_EXPIRED(TIMER - Objective Buffer)
FLAG(Soviet_2/FLAG - Intro Soviet 02 Patrol Destroyed)
PLAYER_HAS_OBJECT_COMPARISON(Soviet_1, 1, 0, "objective 01 - soviet infantry")
```

- 第二个 flag 由 `Soviet_2` 组的 `TEAM_DESTROYED(TEAM - Intro Patrol 01)` 写入 —— 是那支**开场巡逻队**整队被消灭。
  名字里的 `Soviet 02` 是路径组名，不是「第二波」。
- 第三个条件是对象列表计数：该列表由 `OBJECTLIST_ADDOBJECTTYPE` 加了两条 ——
  `sovietantiinfantryinfantry` 与 `sovietscoutinfantry`。要求 Soviet_1 名下这两类单位**数量为 0**。
- 所以只清掉巡逻队不够；只要场上还剩一个这类步兵（或归属被改成别人导致计数异常），目标就不会完成。

### 苏军第八关 `S08_Destroy_Emissary`

两组，任一组成立即完成：

```
OR0: FLAG(f_objective_display_active) == 0   AND   FLAG(f_emissary_was_destroyed) == 1
OR1: FLAG(f_debug_skip_objective_01) == 1
```

- 该图**自带**一条调试跳过分支（`f_debug_skip_objective_01`），不必真的击毁特使。
- `f_emissary_was_destroyed` 由 `NAMED_NOT_DESTROYED(o_allied_emissary)` 等条件组写入，要求特使确实「被毁」
  且护卫队清空；特使以其它方式离场时不写。
- 脚本层面盟军体系完整存在（`Allies01`、`o_allied_emissary`、`Allied_Guards_All`），不是缺阵营。

## 二、数据从哪来

目标表的来源有两条，**运行时优先用第二条**：

| 来源 | 何时用 | 覆盖范围 |
|---|---|---|
| 内置表 `src/generated/objectives_data.h` | 脚本解析失败（不在对局里、地图不是 NWB 格式、读取受限） | 官方 27 张战役图 |
| 关卡脚本（运行时解析） | 进关后自动生成，成功即替换内置表 | 当前这一关，含 mod 图 / 其他版本 |

### 2.1 判定规则（两条来源共用）

- **锚点**：脚本动作 `SET_MISSION_OBJECTIVE_STATUS(目标名, 2)` 与
  `MARK_MISSION_OBJECTIVE_COMPLETED(目标名)` 都表示"把该目标标记为完成"。
  不用猜 `Objective NN - Completed` 这类命名（各图写法不统一），直接看动作。
  — 后者是苏军 J02/J03 的唯一写法；只认前者，那两张图会得到空表。
- 该动作所在脚本的每个 `OrCondition` 分组 = **一条完成路径**（任一路径成立即完成）。
- 路径里的 `FLAG` / `TIMER_EXPIRED` 条件 = **可直接拨动的依赖**；
  其余条件（`NAMED_DESTROYED`、`PLAYER_HAS_OBJECT_COMPARISON` 等）无法用 flag 满足，
  记为 `other` 计数，UI 会提示"另有实体条件"。

规模：**27 张图 / 153 个目标 / 188 条完成路径**。

### 2.2 运行时解析链路

```
GameLogic+0x98  →  当前地图相对路径（如 data\maps\official\camp_a01_...\camp_a01_....map）
      ↓
.big 索引查找 → 取条目原始字节（明文；散文件优先，mod 覆盖走这条）
      ↓ refpack 解一层 → "EAR\0" + 8 字节头 + 内层 refpack → 再解一层
      ↓
CkMp 名字池 → PlayerScriptsList → ScriptList → ScriptGroup/Script → OrCondition/ScriptAction
      ↓
生成与内置表同格式的 M| / O| token 行 → 替换表
```

| 环节 | 实现 | 说明 |
|---|---|---|
| BIG4 索引 | `src/big4.cpp` | 头 = `BIG4` + u32LE 总长 + u32BE 条目数 + u32BE 索引长；索引项 = u32BE 偏移 + u32BE 长度 + 名字 |
| refpack | `src/refpack.cpp` | 头 5 字节里带解压后长度，按它一次性分配；越界即判失败，不猜 |
| 脚本树 | `src/maptbl.cpp` | 严格顺序读；任何越界都整体放弃并回落内置表，不做"尽力修复" |
| 接入 | `scriptobj.cpp` `ObjTableUseScript()` | 由 HTTP `/objectives` 与 UI「扫描当前关卡」触发（都在后台线程） |

耗时：单图 **16–60 ms**（读索引 + 两层解压 + 遍历几百个脚本）。

比对口径：`research/tools/verify_maptbl.py` 把运行时结果与内置表逐行对齐，
**27 张图 215 行全部一致** —— 移植与离线生成器等价，不是"看起来差不多"。

## 三、运行时怎么定位

脚本 flag 与 timer 各是一张 `std::map<{scope,hash}, value>`，都是 `ScriptEngine` 的成员。
**表在哪、节点怎么排、键怎么比，全部由静态定位确定** —— 不再"全内存搜哈希 + 启发式筛候选"。

| 项 | 值 |
|---|---|
| 全局入口 | `TheScriptEngine = [0x00CDD190]`（RVA `0x8DD190`；exe 无 ASLR） |
| timer 表 | `ScriptEngine + 0x16CC8` |
| flag 表 | `ScriptEngine + 0x16CE4`（与 timer 相邻，间距 `0x1C`） |
| 表内布局 | `+0x04` 内嵌哨兵（R/L/P）、`+0x0C` root、`+0x10` 哨兵 color；空表时哨兵自指 |
| 节点 | `+0x00 right / +0x04 left / +0x08 parent / +0x0C color / +0x10 scope / +0x14 hash / +0x18 value` |
| 键 | `{scope, hash}`，两者都是 FNV-1（先乘 16777619 再异或字节，起始 `0x811C9DC5`） |
| 比较 | 先 scope 后 hash，都是无符号；key > node 走 right，key < node 走 left |
| 值 | **只有最低字节有效**（引擎按 bool 写），高 3 字节是分配器残留 |

各条结论的证据（都能在 exe 里复现）：

| 事实 | 证据 |
|---|---|
| 两张表的偏移 | `0x19E825` 的 xfer 遍历读 `[ebx+0x16CC8]`；`0x173B9C` / `0x18A98A` 的读写用 `[edi+0x16CE4]` |
| 节点字段与比较顺序 | `0x171370`（map::find）：`[eax+0x10]`/`[eax+0x14]` 比键，`[eax]`/`[eax+4]` 走右/左 |
| 值只看低字节 | `0x489C10` 的 `cmp byte ptr [eax], 0`（GetFlag 的调用方） |
| 空作用域 = `0x811C9DC5` | `0x173B42` 的 FNV 初值；`[engine+0x17D60]` 为空串时就是它 |
| 插入入口 | `0x18A8F0`：引擎的 get-or-create，`ret 4`，返回 `&node->value` |

**自检**：`GET /scripttbl` 会给出 `badParent`（父子互指失败数）与 `unsorted`（中序键逆序数）。
两项都为 0，才说明"读到的确实是一棵完整的红黑树"—— 这是判断偏移有没有跑偏最快的手段：

```
ready=1  engine=039A8B80  flagRoot=0781FA80  flagCount=79
timerRoot=06076DF8  timerCount=110  badParent=0  unsorted=0
```

写入语义：

| 依赖类型 | 操作 |
|---|---|
| `F`（FLAG） | 低字节置 1，高位保留 |
| `N`（取反 FLAG） | 低字节置 0 |
| `T`（TIMER） | 整体写 **`0x00000000`** = 已过期；`0xFFFFFFFF` = 建过但**从未启动**（不是过期） |

### 版本差异：偏移是"首选"，不是"唯一"

上面的 `+0x16CC8 / +0x16CE4 / [0x00CDD190]` 都是 v1.12.3444 上的值。别的版本、改过的 exe
上这些数字都可能变，所以定位做成两段：**先按已知偏移试，结构自检不过就在 engine 对象里重搜**。

自检只用三条硬条件（都从静态语义推出来，不是启发式）：

1. `[map+0xC]` 是合法堆指针（root）
2. root 的 `+0x08`（parent）**等于** `map+4`（内嵌哨兵地址）—— 真 map 的根一定挂在内嵌哨兵上
3. 全树父子互指**零失败** —— 把别的数据当节点，几乎必然崩在这一步

搜到多个候选后按值的形状分类：`0xFFFFFFFF` 占多数的是 timer，低字节 `0/1` 占多数的是 flag。

`/scripttbl` 会回报实际用的偏移与来源：

```
flagOff=16CE4  timerOff=16CC8  locate=1     # 1 = 已知偏移自检通过（最快）
flagOff=16CE4  timerOff=16CC8  locate=2     # 2 = 自动搜到（偏移已挪动）
```

验证方式是把已知偏移**故意改错 0x10 字节**再跑：`locate` 变 2，两张表的偏移仍被准确找回，
节点数与结构校验不变。

### timer 的值：`0` = 过期，`0xFFFFFFFF` = 从没启动

这条早期记反了（曾按「`0xFFFFFFFF` = 已过期」实现），实测三处证据：

1. 表里在跑的 timer 是**倒计时**：`raw` 从 `0x43` → `0x40`（剩余帧数）。
2. A02 开场 `TIMER - Objective 01 - Complete`、`TIMER - Objective 4 - Complete` 都是
   `0xFFFFFFFF`，而这两个目标显然没完成 —— 若 `-1` 算过期，目标会自己打勾。
3. A01 一局里 110 个 timer **全部**是 `0xFFFFFFFF`，同样说明那是初始值。

所以判状态：`v == 0` → 已过期；`v == 0xFFFFFFFF` → 建过没启动（按"未满足"处理）；
节点不存在 → `absent`。要"强制让某条 timer 过期"，写 `0`。

**表里没有的 flag**：`POST /flagmk?name=<名字>` 让引擎自己插入。必须走引擎的插入 ——
节点要用引擎的分配器（map 析构时会 free），插入要走红黑树旋转与着色。自己拼节点挂链，
一旦结构与引擎的查找路径不一致，就退化成"写进去没人读"。

## 四、关卡自动识别

一次扫描只收"目标表里出现过的依赖 hash"，然后用**稀有度加权**打分：
每个依赖按"它出现在多少张图里"取反比权重（`1000/df`）。

共享名（`TIMER - Objective Buffer` 几乎每关都有）几乎不区分关卡；
独有名字（`FLAG - Intro Soviet 02 Patrol Destroyed`）才是判据。取总分最高的图。

## 五、限制

1. **`other > 0` 的路径光拨 flag 不一定打勾** —— 那些路径还要求"某单位已被摧毁""某玩家对象数为 0"
   之类的实体条件。这类只能靠真打，或者另想它法（造单位 / 杀单位）。
2. **`节点不存在` 现在是可修的**：`/flagmk` 让引擎建表项。但建出来的作用域是"当前作用域"
   （通常是 `0x811C9DC5` 无前缀）。若某脚本的 flag 在别的命名作用域下，建了也读不到 ——
   这种情况先 `/scripttbl?name=` 看同族 flag 的 scope 是否一致。
3. **建过的节点删不掉**（引擎没有暴露删除）。写 0 之后状态是"存在但为假"（`no`），
   与"从未出现过"（`absent`）的显示会不同 —— 判断"脚本到底写过没有"要用 `absent`，不要用 `no`。
4. 查表是纯读内存，微秒级，HTTP 线程直接跑即可；**写入与建表项必须投渲染线程**（会改引擎的 map）。
5. **脚本表只覆盖"当前这一关"** —— 换关后地图名一变就会重建。所以切换关卡后，第一次
   `/objectives` 或第一次点「扫描当前关卡」会多花几十毫秒。
6. **找不到 `.map` 时不会猜**：只有松散文件与 `exe 目录 / Data 子目录` 下的 `.big` 会被查；
   mod 若把地图放在自己的包目录且没被这些路径覆盖，会回落内置表（该图不在 27 张里时就是空表）。
7. **解析失败一律回落，不"尽力修复"**：脚本树是严格顺序结构，任何一处越界都说明这份
   `.map` 不是预期格式（别的引擎版本 / 非 NWB 导出），此时半成品比没有更糟。

## 六、已验证案例

- **A01 盟军第 1 关**：`Objective 01 - Destroy Soviets` 卡在
  `FLAG(Soviet_2/FLAG - Intro Soviet 02 Patrol Destroyed)`（日冕下苏联无单位 → 队伍空 →
  `TEAM_DESTROYED` 虽成立但值一直为 0）。把节点 `0x0442d8b8` 的 value `0x006E6F00` → `0x006E6F01`
  后 3 秒内 `FLAG - Objective 01 Completed` 由 0 变 1，整段 DO 执行，目标打勾。
- **S08 苏联第 8 关**：`f_debug_skip_objective_01` 置 1 → 跳过"伏击特使"整段。
