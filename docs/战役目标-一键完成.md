# 战役目标：自动识别 + 一键完成

> 用途：战役卡进度时，不必猜"哪个条件没满足"，直接列出本关所有目标、每条完成路径依赖哪些
> flag/计时器，点一下就把它们全拨到位 —— 脚本下一帧自己执行原有的 DO 块（打勾、挂后续计时器、
> 解除建筑无敌、推进剧情），**走的是脚本本来的判定路径，不是伪造进度**。

## 一、怎么用

修改器菜单（默认 `INSERT`，可在启动器里改）→ **杂项操作** → **战役目标（自动识别 · 一键完成）**

1. 点「扫描当前关卡」→ 等约 10 秒（后台线程，期间游戏可正常操作）
2. 顶部显示识别到的关卡名与脚本节点数
3. 每个目标可展开，列出所有完成路径；每条路径下列出每个依赖项及其当前状态
   （`满足` / `未满足` / `节点不存在`）
4. 点「完成这条路径」→ 把该路径的 flag/计时器全部拨到位

HTTP 等价接口：

```
GET  /objectives                 # 扫描 + 列出（文本，含每个依赖的当前状态）
POST /objdone?i=<目标序号>[&p=<路径序号>]   # 完成；省略 p 则自动选实体条件最少的一条
GET  /objdbg                     # 目标表解析结果（排查用）
POST /flag?name=<名字>&on=1|0    # 任意脚本 flag，按名字自动匹配作用域
```

**修复卡关**（杂项操作页，目标面板上方）：识别当前关卡后，把**第一个未完成目标**按它最省的一条
依赖路径拨到位 —— 与「完成这条路径」按钮同一套写入，脚本下一帧自己执行 DO 块。

- 只推进一个目标：一次全推会越过剧情，卡关要解的是当前这道坎。
- 目标表覆盖不到的图，回退为把地图自带的 `f_debug_skip_objective_01..04` 置 1。
- 查找放后台线程（一次全内存扫描约 10 秒，期间可正常操作），写回在渲染线程；
  回退路径的批量定位走 `ScriptFlagResolveBatch()`，不必为每个 flag 各扫一遍内存。

### 关卡识别：按地图文件

主判据是**当前地图路径**：`[0x00CD8CE4]`（TheGameLogic）`+0x98` 是 C 串，
实测形如 `data\maps\official\CAMP_S09_NewYork_Rao\CAMP_S09_NewYork_Rao.map`。
取 basename、去 `.map`、转小写后与目标表里的关卡名匹配，命中即用（`/objectives` 里显示 `score=9999`）。

这条读不到时才退回「脚本节点命中率」启发式 —— 那条**不可靠**：`TIMER - Objective Buffer`
几乎每张图都有，依赖项最多的 A01 曾经永远是最高分。因此面板保留了 **关卡下拉** 可以手动指定，
「修复关卡剧情异常」也吃同一个选择。


## 附：两张卡关图的脚本原文

目标完成条件在脚本里是 `orGroups` 的嵌套结构：组与组之间是**或**，同组内的条件之间是**与**。
调试器把每组展成一条「路径」，所以一条路径里既有 flag/timer，也可能有实体条件（记为 `other`）。

### 盟军第一关 `Objective 01 - Completed`

单组，三条同时成立：

```
TIMER_EXPIRED(TIMER - Objective Buffer)
FLAG(Soviet_2/FLAG - Intro Soviet 02 Patrol Destroyed)
PLAYER_HAS_OBJECT_COMPARISON(Soviet_1, 1, 0, "objective 01 - soviet infantry")
```

- 第二个 flag 由 `Soviet_2` 组的 `TEAM_DESTROYED(TEAM - Intro Patrol 01)` 写入 —— 是那支**开场巡逻队**整队被消灭。
  名字里的 `Soviet 02` 是路径组名，不是「第二波」。
- 第三个条件是对象列表计数：该列表由 `OBJECTLIST_ADDOBJECTTYPE` 加了两条 ——
  `sovietantiinfantryinfantry` 与 `sovietscoutinfantry`。要求 Soviet_1 名下这两类单位**数量为 0**。
- 所以只清掉巡逻队不够；只要场上还剩一个这类步兵（或归属被改成别人导致计数异常），目标就不会完成。

### 苏军第八关 `S08_Destroy_Emissary`

两组，任一组成立即完成：

```
OR0: FLAG(f_objective_display_active) == 0   AND   FLAG(f_emissary_was_destroyed) == 1
OR1: FLAG(f_debug_skip_objective_01) == 1
```

- 该图**自带**一条调试跳过分支（`f_debug_skip_objective_01`），不必真的击毁特使。
- `f_emissary_was_destroyed` 由 `NAMED_NOT_DESTROYED(o_allied_emissary)` 等条件组写入，要求特使确实「被毁」
  且护卫队清空；特使以其它方式离场时不写。
- 脚本层面盟军体系完整存在（`Allies01`、`o_allied_emissary`、`Allied_Guards_All`），不是缺阵营。

## 二、数据从哪来

`research/tools/gen_objective_table.py` 解析 27 张战役图的脚本树（`campaign_script_dump.py`），
生成 `ra3-copilot/src/generated/objectives_data.h`：

- **锚点**：脚本动作 `SET_MISSION_OBJECTIVE_STATUS(目标名, 2)` 就是"把该目标标记为完成"。
  不用猜 `Objective NN - Completed` 这类命名（各图写法不统一），直接看动作。
- 该动作所在脚本的每个 `OrCondition` 分组 = **一条完成路径**（任一路径成立即完成）。
- 路径里的 `FLAG` / `TIMER_EXPIRED` 条件 = **可直接拨动的依赖**；
  其余条件（`NAMED_DESTROYED`、`PLAYER_HAS_OBJECT_COMPARISON` 等）无法用 flag 满足，
  记为 `other` 计数，UI 会提示"另有实体条件"。

规模：**25 张图 / 141 个目标 / 174 条完成路径 / 113 个不同依赖**。

## 三、运行时怎么定位

脚本 flag 与 timer 共用 SAGE `ScriptEngine` 内的 `std::map<NameKey,int>`：

| 项 | 值 |
|---|---|
| 三张表 | `ScriptEngine+0x16CA8`(timer) / `+0x16CC4`(flag) / `+0x16CE0`(其它) |
| 键 | 8 字节 `{作用域哈希, FNV-1(名字)}`；作用域不固定（`0x811C9DC5` 只是"无前缀"的一种） |
| 节点 | `+0x00 L / +0x04 P / +0x08 R / +0x0C color / +0x10 scope / +0x14 hash / +0x18 value` |
| 名字哈希 | **FNV-1**（先乘 16777619 再异或字节，起始 2166136261） |

定位方式：**搜 4 字节 hash** → 候选节点 = 命中地址 − `0x14` → 校验 L/P/R 为 0 或堆地址
（优先采信 `P` 合法的"在树里"的候选）。**不要遍历红黑树** —— SAGE 用的是自有实现
（根/游离节点 `P = 0`），DFS 会把 101 条的表只走出 28 条。

写入语义：

| 依赖类型 | 操作 |
|---|---|
| `F`（FLAG） | value 的 **bit0 置 1**（其余位另有用途，不能整体覆盖） |
| `N`（取反 FLAG） | bit0 清 0 |
| `T`（TIMER） | 整体写 `0xFFFFFFFF` = **已过期**（`0x00000000` = 未触发/正在跑） |

## 四、关卡自动识别

一次扫描只收"目标表里出现过的依赖 hash"，然后用**稀有度加权**打分：
每个依赖按"它出现在多少张图里"取反比权重（`1000/df`）。

共享名（`TIMER - Objective Buffer` 几乎每关都有）几乎不区分关卡；
独有名字（`FLAG - Intro Soviet 02 Patrol Destroyed`）才是判据。取总分最高的图。

## 五、限制

1. **`other > 0` 的路径光拨 flag 不一定打勾** —— 那些路径还要求"某单位已被摧毁""某玩家对象数为 0"
   之类的实体条件。这类只能靠真打，或者另想它法（造单位 / 杀单位）。
2. **`节点不存在` 的依赖会被跳过** —— 引擎只在脚本"跑过一次 SET"后才建表项；
   如果某 flag 从未被 SET 过，表里就没有它，拨不动。
3. **同 hash 不同作用域**只取一个（不同前缀的同名 flag 极少见；真遇到要扩展成多候选）。
4. 扫描 ~10 秒走 HTTP / 后台线程，**绝不能放渲染线程**（会卡死游戏，有前科）。

## 六、已验证案例

- **A01 盟军第 1 关**：`Objective 01 - Destroy Soviets` 卡在
  `FLAG(Soviet_2/FLAG - Intro Soviet 02 Patrol Destroyed)`（日冕下苏联无单位 → 队伍空 →
  `TEAM_DESTROYED` 虽成立但值一直为 0）。把节点 `0x0442d8b8` 的 value `0x006E6F00` → `0x006E6F01`
  后 3 秒内 `FLAG - Objective 01 Completed` 由 0 变 1，整段 DO 执行，目标打勾。
- **S08 苏联第 8 关**：`f_debug_skip_objective_01` 置 1 → 跳过"伏击特使"整段。
