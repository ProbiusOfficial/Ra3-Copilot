## 一、RVA / 结构偏移总表（基于 CE，已逐字节验证）

以下地址与偏移基于 CE 修改器，并对本机 `ra3_1.12.game` 逐字节验证（含每个功能挂钩点的
原始指令 + 洞内动作）。游戏 ImageBase `0x400000`。

| 名称 | RVA | 说明 |
|---|---|---|
| 玩家管理器 | `0x8E08DC` | 全局指针 → mgr；`mgr+0x50` = 选中链表头，`mgr+0x5c` = 选中数量 |
| 对象模板库 | `0x8E6C58` | 全局指针 → store |
| 当前对象哈希 | `0x8E9838` | 当前操作对象的类型哈希 |
| 光标坐标 | `0x8DAEFC` | 全局指针 → 坐标对象；`+0x3c`=x `+0x40`=y `+0x44`=z |
| 模板查找 | `0x3E4230` | `__thiscall(this=store, hash)` → `template*` |
| **创建单位** | `0x2440F0` | `cdecl(0, template, float* pos, team, team+0x10)` → `object*` |
| 地形吸附 | `0x1ED4A0` | `cdecl(float* src, float* dst, int, int)` |
| 出厂等级(基)车) | `0x35C200` / `0x39EA50` | 备用 |

**单位结构偏移**（相对 `obj` 与 `body`）：
| 字段 | 位置 |
|---|---|
| body | `[obj+0x138]` |
| 血量体 | `[body+0x33c]`；`+4`=当前, `+0xc`=上限, `+0x10`=备份 |
| 归属玩家对象 | `[body+0x418]` |
| 速度链 | `[body+0x374]` → `[+0x200]` → 子节点数组；节点 `+8`=速度, `+0x40`=备份（第二节点还需 `[+0x18]==1.0f`） |

**链表遍历**：`node = [mgr+0x50]`；`obj = [node+8]`；`node = [node]`；共 `[mgr+0x5c]` 次。

## 二、已实现的功能

| 功能 | 实现 |
|---|---|
| **超速 / 慢速 / 冻结 / 恢复速度** | 遍历选中单位 → 速度链节点设 `500 / 10 / 0`（改前写备份 `+0x40`）；恢复=写回备份 |
| **无敌 / 残血 / 恢复血量** | 血量体 `+4`(和 `+0xc`) 设 `999999 / 1.0`；恢复=`+0x10` → `+4,+0xc` |
| **收编敌方（复制到己方）** | 选中单位 `[body+0x418] = 本地玩家对象`；若"当前对象哈希"是 6 个超武之一则跳过（基于 CE） |
| **摧毁选中** | 血量体 `+4=+0xc=0` → 引擎判定死亡 |
| **召唤单位（支援代码/哈希）** | `FindTemplate(hash)` → `CreateUnit(0, tmpl, pos, 本地玩家, [玩家+0x10])` × N |
| **召唤基地车** | 同上，用 3 个 MCV 哈希（`0x28DA574E / 0xAF4C0DA5 / 0x1C2EF767`） |
| **空投箱** | 同上，箱子哈希取自 `units_corona.h` 的 `kCrates[]`（54 种） |

落点：优先**首个选中单位**的位置；没有选中则用**鼠标光标**坐标。

## 五、风险与后续

- 这些是**直接改游戏内存 + 调游戏函数**，全部用 SEH 包裹 + 空指针校验；但**参数契约若与游戏版本不符仍可能崩**。
  所有动作都是**用户手动触发**，不会自动跑。
- **未实现**（尚未接入）：
  `协议无冷却 / 单位技能无冷却 / 禁用敌方协议 / 弹药无限(*) / 满级 / 一键满状态 / 混乱模式 /
   刷矿车车队 / 出场等级 / 单位属性检视`
  （`*` 弹药无限其实已有 FLAGS+0x12 钩子）
- **按名字召唤**：运行时扫模板库找哈希 → 可解锁任意对象（含基础版 `UnitCrate`）。

## 七、★★★ 地址表修正（2026-10-14 实测）

基于 CE 的地址表（针对 1.12.3444.25830），其 18 处偏移已对本机 `Data\ra3_1.12.game` 逐字节验证。
原表有三个 RVA 与本机构建不符，修正后实测可用：

| 项 | 原值（❌ 对本构建） | **修正后（✅ 实测可用）** |
|---|---|---|
| 创建单位 | `0x2440F0`（落在指令中间） | **`0x205240`** — `cdecl(0, tmpl, float* pos, team, team+0x10)`（干净函数入口，`8b4c2408 83ec3c 53`） |
| 选中管理器 | `0x8E08DC`（恒为 0） | **`0x8DB73C`** — `+0x50` 链表头 / `+0x5c` 数量（实测 `[0x8DB73C]=0x36209b0, +0x5c=1` ✅） |
| 光标坐标 | `0x8DAEFC`（指向全零对象） | 用 `MOD+0x1ED4A0`（鼠标地图坐标函数） |

**其它可用项**（均实测为干净入口）：
| 功能 | RVA | 调用 |
|---|---|---|
| 单位升级（满级） | `0x35C200` | `ecx=unit, cdecl(3, 1, 0)` |
| 击杀选中 | `0x39EA50` | `ecx=unit, cdecl(6, 19, 0)` |
| 模板查找 | `0x3E4230` | `ecx=[0x8E6C58], arg=hash` |
| 鼠标地图坐标 | `0x1ED4A0` | — |
| **免费建造** | **`0x0E7565`** | 字节 `75 0C`(jne) → **`EB 0C`**(jmp)，建造检测恒真 |

### 顺带修掉的两个真 bug
1. **迷雾去除无效**：`MapCaveStub` 原本是「先写 `[ebp+0x260]=100000` → 再重放原指令 `movss [ebp+0x260],xmm0`」，
   而**原指令本身就是写这个字段**，于是我们的值被它冲掉。正确顺序是**先重放原指令、再覆盖** → 已按此修正。
2. **快速建造会导致建造卡死**：我们的 `FastBuild3CaveStub` 写的是 `[esi+0x1bc]=100`，
   而该挂钩点**不应碰 `[esi+0x1bc]`**（那是别的计时器），只做 `[edi+0x14] = [edi+0x3c] + 1`
   （且 `ebp==1` 时跳过）。已按此改写 → 建造队列保持一致，不再卡死。
   ★ 另外新增更安全的 **免费建造**（1 字节补丁），不想用快建时用它。

## 八、★★ 版本兼容：符号解析器（AOB + 结构推导），不再硬编码 RVA

> 起因：CE 表只对 1.12 有效。要求改成"按字段/汇编反推"，尽量兼容其它版本与 mod。

**实现**：`src/symres.{h,cpp}`。解析顺序（每个符号独立）：

1. **特征码（AOB）全模块扫描** —— 唯一命中即用；
2. **多命中** → 取"离 1.12 已知 RVA 最近"的那个（版本小改时地址不会跑远）；
3. **0 命中** → 退回已知 RVA，但**必须通过函数入口形态校验**，否则标为解析失败（不盲调）。

**全局变量用结构推导，不靠固定地址**：

| 符号 | 依据 | 本机 1.12 实测 |
|---|---|---|
| ThingFactory 全局 | 先解析 `TmplFind`，再找 `8B 0D <imm32> E8 <rel32→TmplFind>` 的代码，取**出现次数最多**的 imm32 | **110 处代码一致**指向 `0xCE6C58` ✅ |
| 选中管理器全局 | 扫 .data：`[V+0x5c]∈1..64`、`[V+0x50]` 链表首对象及其 body 的 **vtable 都落在主模块内** | 仅 2 个候选，取最近的 = `0x8DB73C` ✅ |

**特征码唯一性（实测）**：`CreateUnit`(1) · `MouseMap`(1) · `LevelUp`(1, 20B) · `FreeBuildSite`(1, 20B) ·
`TmplFind`(2 → 用 ThingFactory 推导命中数判别真身) · `KillUnit`(3 → 就近)。

**自愈能力**：换版本后若 RVA 漂移，只要**特征码还在**（编译差异通常不改这些字节序列）就能重新定位；
`TmplFind` 这类同形函数用"结构关系"判别，比单看字节更稳。
每次启动把解析结果与来源写进「输出记录」（`[符号] 创建=... (AOB唯一) ...`），诊断页也会打印。

**残留硬编码**：`0xDAEFC(光标全局)` / `0x8E9838(当前对象哈希)` 仅作兜底与"超武跳过"判断，不参与主链路。

## 九、对象模型补充（2026-10-15 ~ 10-16 实测）

### 1. Drawable 与 Thing 是两套指针，别混

| | 真实单位（Drawable） | 引擎对象（Thing） |
|---|---|---|
| vtable | `0x00BED890` | `0x00C4DB60` |
| 取对方 | `[drawable+0x138]` = Thing | —— |
| `+0x418` | **恒为 0** | = 归属 Team |

- **选中链拿到的是 Drawable**（`[[SelMgr]+0x50]` 链 → `node+8`）。
- **`CreateUnit` 返回的是 Thing**。
- **升级目标** = `[[obj+0x138]+0x3CC]`；**收编** = 把 `[Thing+0x418]` 写成本地 Team；
- **选中落点** = `[[SelMgr]+0x50]` 链 → `node+8`(Drawable) → `[d+0x138]` → `+0x38/0x3c/0x40`。

### 2. Thing 偏移速查

| 偏移 | 含义 |
|---|---|
| `+0x04` | 模板指针（模板 `+0x08` = 类型哈希） |
| `+0x33c` | 血量体（`+4` 当前 / `+0xc` 上限 / `+0x10` 备份） |
| `+0x418` | 归属 Team |
| `+0x374` | AIUpdate |
| `+0x38/0x3c/0x40` | 坐标 x/y/z |
| `+0xDC` | 对象 ID |
| `+0x80/0x84/0x88/0x90/0x94/0xD0` | 状态字（见下） |

### 3. 状态字决定护盾 / 技能回复

召唤、复制出来的单位如果状态字不对，会表现为"隐形"：小地图空心、敌方不攻击、反隐贴近才变实心。
正确写法（**创建后必须做后处理**，`actions.cpp` 的 `SummonByHash`）：

- 激活态：`{+0x80:0, +0x84:0x800, +0x88:0, +0x90:0x2, +0x94:0x20, +0xD0:0}`
- 隐形态（错误值）：`{+0xC8:0x800, +0x28:0x80000000, +0x208:0x80000000}` → 清成 `0` 即恢复
- ⚠️ `+0x90` / `+0x94` 会被引擎逐帧重算，所以**不能只在创建瞬间写一次**，要放在创建函数的后处理里。

> 根因分析全文：`docs/召唤单位状态字-根因与修复.md`。
