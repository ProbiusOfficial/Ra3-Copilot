## 一、RVA / 结构偏移总表

以下地址与偏移基于 CE 修改器，并对本机 `ra3_1.12.game` 逐字节验证（含每个功能 hook 点的
原始指令 + cave 内动作）。游戏 ImageBase `0x400000`。

| 名称 | RVA | 说明 |
|---|---|---|
| 玩家管理器 | `0x8DB73C` | 全局指针 → mgr；`mgr+0x50` = 选中链表头，`mgr+0x5c` = 选中数量（CE 原值 `0x8E08DC` 对本构建恒为 0，已弃用） |
| 对象模板库 | `0x8E6C58` | 全局指针 → store |
| 当前对象哈希 | `0x8E9838` | 当前操作对象的类型哈希 |
| 光标坐标 | `0x8DAEFC` | 全局指针 → 坐标对象；`+0x3c`=x `+0x40`=y `+0x44`=z |
| 模板查找 | `0x3E4230` | `__thiscall(this=store, hash)` → `template*` |
| **创建单位** | `0x205240` | `cdecl(0, template, float* pos, team, team+0x10)` → `object*`（CE 原值 `0x2440F0` 对本构建落在指令中间，已弃用） |
| 屏幕像素 → 世界坐标 | `0x1ED4A0` | `cdecl(void* src, void* dst, int, int)`；`src` = 客户区像素 (x, y, 上下文) 三个 dword，输出该像素射线命中的**地形表面世界坐标（含高度）**。第三参数不参与运算 |

**单位结构偏移**（相对 `obj` 与 `body`）：
| 字段 | 位置 |
|---|---|
| body | `[obj+0x138]` |
| 血量体 | `[body+0x33c]`；`+4`=当前, `+0xc`=上限, `+0x10`=备份 |
| 归属玩家对象 | `[body+0x418]` |
| 速度链 | `[body+0x374]` → `[+0x200]` → 子节点数组；节点 `+8`=速度（第二节点还需 `[+0x18]==1.0f`）。原速备份由修改器自己记账（节点地址 → 原速），不用 CE 那套 `+0x40` 槽 |

## 二、已实现的功能

| 功能 | 实现 |
|---|---|
| **移速（单位面板滑条）** | 遍历选中单位 → 速度链节点 `+8` 写入滑条值（`0` = 定住，量程 `0..1000`；松手/回车才写入）。改前把原速记进修改器自持的备份表（键 = 节点地址），「恢复原速」写回该值 |
| **超速 / 慢速 / 定住 / 恢复（热键 + HTTP `/speed`）** | 同一套读写路径，档位值 `500 / 10 / 0`，恢复走同一个备份表（面板四按钮已并为滑条） |
| **无敌 / 残血 / 恢复血量** | 血量体 `+4`(和 `+0xc`) 设 `999999 / 1.0`；恢复=`+0x10` → `+4,+0xc` |
| **收编敌方（归属改为己方）** | 选中单位 `[body+0x418] = 本地玩家对象`；若"当前对象哈希"是 6 个超武之一则跳过（基于 CE） |
| **摧毁选中** | 调 `KillUnit`（RVA `0x39EA50`，`ecx=Thing`，栈参 `(6,19,0)`）。别在游戏流程**之外**直接写血量 0 —— 会留下「幽灵单位」（对象不回收、模型仍在）；「秒杀」hook 因在流程**内**改写，不受此限 |
| **召唤单位（支援代码/哈希）** | `FindTemplate(hash)` → `CreateUnit(0, tmpl, pos, 本地玩家, [玩家+0x10])` × N |
| **召唤基地车** | 同上，用 3 个 MCV 哈希（`0x28DA574E / 0xAF4C0DA5 / 0x1C2EF767`） |
| **空投箱** | 同上，箱子哈希取自 `units_corona.h` 的 `kCrates[]`（55 种） |
| **单位状态（铁幕 / 无敌 / 加速 / 减速 / 易碎 / 输出增强 / 重置）** | **表驱动**（`actions.cpp` 的 `kUnitStatus[]` + `ActUnitStatus`）：当前 6 项状态均只挂引擎 modifier（`0x7181F0` 施加 / `0x718300` 解除）；表结构另支持 ObjectStatus（`Object::SetStatus`）与定身 / 易碎联动，现表未启用。「重置」= 撤全部 modifier + 速度还原 + 血量回满。UI：单位面板「单位状态」组（下拉 + 施加/解除/重置）；HTTP：`/status`。**不写引擎槽位内部字段**（见 §九.7） |

落点三来源（按 UI「落点来源」设置排序，默认**视野中心**优先；也可用 `/summon?place=` 单次点名，
或用 `?x=&y=&z=` 直接指定坐标）：

| 来源 | 取法 | 可靠性 |
|---|---|---|
| **视野中心** | 游戏客户区**正中的像素** → 换算函数 `0x1ED4A0` → 命中的地面世界坐标 | 稳。不依赖相机矩阵，也不依赖鼠标；窗口失焦照样对 |
| **选中单位** | 首个选中单位 `body+0x38/+0x3c/+0x40` | 稳。前提是有选中 |
| **游戏光标** | `[0x8DAEFC]` 对象 `+0x3c/+0x40/+0x44` → 同一个换算函数 | **只在鼠标位于游戏窗口内时刷新**。玩家切出去（例如与 AI 对话）时它停在旧值 → 投到"上次鼠标停留处"，那个点在水面就落海 |

> **为什么不用 d3d9 相机矩阵反投影**：实测游戏 `SetTransform(D3DTS_VIEW)` 传的矩阵 `_33` 恒为 1.0
> （单位矩阵），3D 相机根本不走那条通道 —— 反投影此路不通。

## 六、实测定位

CE 地址表中有 3 个 RVA 对本机构建失效：创建单位 `0x2440F0` 落在指令中间、选中管理器 `0x8E08DC` 恒为 0、
光标 `0x8DAEFC` 指向全零对象。修正值见 §七。

SEH 会静默吞掉调用异常，失败时看 `SummonLastError()` —— 它精确报出失败环节（模板库空 / 模板未找到 /
玩家为 0 / 玩家+0x10 空 / 落点取不到 / 地址不匹配 / 调用异常 / 返回空）。

## 七、地址表修正

基于 CE 的地址表（针对 1.12.3444.25830），其 18 处偏移已对本机 `Data\ra3_1.12.game` 逐字节验证。
原表有三个 RVA 与本机构建不符，修正后实测可用：

| 项 | 原值（❌ 对本构建） | **修正后（✅ 实测可用）** |
|---|---|---|
| 创建单位 | `0x2440F0`（落在指令中间） | **`0x205240`** — `cdecl(0, tmpl, float* pos, team, team+0x10)`（干净函数入口，`8b4c2408 83ec3c 53`） |
| 选中管理器 | `0x8E08DC`（恒为 0） | **`0x8DB73C`** — `+0x50` 链表头 / `+0x5c` 数量（实测 `[0x8DB73C]=0x36209b0, +0x5c=1` ✅） |
| 光标坐标 | `0x8DAEFC`（指向全零对象） | 仍然用它拿"鼠标处世界坐标"，但要知道它**只在鼠标位于游戏窗口内时刷新**（见 §二 落点三来源） |

**其它可用项**（均实测为干净入口）：
| 功能 | RVA | 调用 |
|---|---|---|
| 单位升级（满级） | `0x35C200` | `ecx=unit, cdecl(3, 1, 0)` |
| 击杀选中 | `0x39EA50` | `ecx=unit, cdecl(6, 19, 0)` |
| 模板查找 | `0x3E4230` | `ecx=[0x8E6C58], arg=hash` |
| 屏幕像素 → 世界坐标 | `0x1ED4A0` | `cdecl(src, dst, 0, 0)`；src=(像素x,像素y,上下文) |
| **免费建造** | **`0x0E7565`** | 字节 `75 0C`(jne) → **`EB 0C`**(jmp)，建造检测恒真 |

### 两个实现要点
1. **迷雾去除**：`MapCaveStub` 必须**先重放原指令 `movss [ebp+0x260],xmm0`、再覆盖**为 `100000` ——
   反序会被原指令冲掉。
2. **快速建造**：`FastBuild3CaveStub` **不碰 `[esi+0x1bc]`**（那是别的计时器），只做 `[edi+0x14] = [edi+0x3c] + 1`
   （且 `ebp==1` 时跳过），建造队列才保持一致。不想用快建时可用更安全的**免费建造**（1 字节补丁）。

## 八、版本兼容：符号解析器（AOB + 结构推导）

> CE 表只对 1.12 有效；此处改为"按字段 / 汇编反推"，以兼容其它版本与 mod。

**实现**：`src/symres.{h,cpp}`。解析顺序（每个符号独立）：

1. **特征码（AOB）全模块扫描** —— 唯一命中即用；
2. **多命中** → 取"离 1.12 已知 RVA 最近"的那个（版本小改时地址不会跑远）；
3. **0 命中** → 退回已知 RVA，但**必须通过函数入口形态校验**，否则标为解析失败（不盲调）。

**全局变量用结构推导，不靠固定地址**：

| 符号 | 依据 | 本机 1.12 实测 |
|---|---|---|
| ThingFactory 全局 | 先解析 `TmplFind`，再找 `8B 0D <imm32> E8 <rel32→TmplFind>` 的代码，取**出现次数最多**的 imm32 | **110 处代码一致**指向 `0xCE6C58`（VA）。本机 ImageBase `0x400000` → RVA `0x8E6C58`，两者是同一地址的两种口径 |
| 选中管理器全局 | 扫 .data：`[V+0x5c]∈1..64`、`[V+0x50]` 链表首对象及其 body 的 **vtable 都落在主模块内** | 仅 2 个候选，取最近的 = `0x8DB73C` ✅ |

**特征码唯一性（实测）**：`CreateUnit`(1) · `MouseMap`(1) · `LevelUp`(1, 20B) · `FreeBuildSite`(1, 20B) ·
`TmplFind`(2 → 用 ThingFactory 推导命中数判别真身) · `KillUnit`(3 → 就近)。

**自愈能力**：换版本后若 RVA 漂移，只要**特征码还在**就能重新定位；
`TmplFind` 这类同形函数用"结构关系"判别，比单看字节更稳。
每次启动把解析结果与来源写进「输出记录」（`[符号] 创建=... (AOB唯一) ...`），诊断页也会打印。

**残留硬编码**：`0xDAEFC(光标全局)` / `0x8E9838(当前对象哈希)` 仅作兜底与"超武跳过"判断，不参与主链路。

## 九、对象模型补充

### 1. Drawable 与 Thing 是两套指针，别混

| | 真实单位（Drawable） | 引擎对象（Thing） |
|---|---|---|
| vtable | `0x00BED890` | `0x00C4DB60` |
| 取对方 | `[drawable+0x138]` = Thing | —— |
| `+0x418` | **恒为 0** | = 归属 Team |

- **选中链拿到的是 Drawable**（`[[SelMgr]+0x50]` 链 → `node+8`）。
- **`CreateUnit` 返回的是 Thing**。

- **选中落点** = `[[SelMgr]+0x50]` 链 → `node+8`(Drawable) → `[d+0x138]` → `+0x38/0x3c/0x40`。

### 3. 状态字决定护盾 / 技能回复

召唤、复制出来的单位如果状态字不对，会表现为"隐形"：小地图空心、敌方不攻击、反隐贴近才变实心。
正确写法（**创建后必须做后处理**，`actions.cpp` 的 `SummonByHash`）：

- 激活态：`{+0x80:0, +0x84:0x800, +0x88:0, +0x90:0x2, +0x94:0x20, +0xD0:0}`
- 隐形态（错误值）：`{+0xC8:0x800, +0x28:0x80000000, +0x208:0x80000000}` → 清成 `0` 即恢复
- `+0x90` / `+0x94` 会被引擎逐帧重算，所以**不能只在创建瞬间写一次**，要放在创建函数的后处理里。

> 根因分析全文：`docs/召唤单位状态字-根因与修复.md`。

仍适用的三条通用结论：

1. 引擎字段分"事件驱动"与"读驱动"。需要通知的（状态位 → 音效 / UI / 行为锁）必须走引擎设置器，
   raw poke 只对读驱动字段有效。
2. `Drawable+0x244` 是引擎拥有的 `std::vector`，析构时会 `free()` 其 buffer，**绝不可写入 DLL 自有内存**。
3. 模型条件必须经 `Drawable::setModelConditionState`（RVA `0x12F360`）配合 `Drawable+0x2DC` 缓冲写入，
   直接 poke `+0x264` 会被每帧重算覆盖。

### 7. modifier 通道（现役）

三个引擎函数，原版即具备（日冕桥只是把它们暴露给 Lua）：

| 用途 | 地址 | 调用形态 |
|---|---|---|
| modifier 库查表 | RVA `0xA6BE0` | `__cdecl (container = 0xC5E07887, nameHash, out)` → modifier 对象 |
| **施加** | RVA `0x3181F0`（VA `0x7181F0`） | `__thiscall (this = Thing, modifier, duration)`，handler 槽 `vtable+0x1D0`，`ret 8` |
| **解除** | RVA `0x318300`（VA `0x718300`） | `__thiscall (this = Thing, modifier)`，handler 槽 `vtable+0x1D8`，`ret 4` |

两者都在 `[Thing+0x328]` 找 handler，再经 handler vtable `+0x84` 取查找器 —— 结构对称。

**`duration` 的单位是「帧」，15 帧/秒**：`10 → 0.67 s`、`100 → 6.6 s`。要 N 秒就传 `N*15`，不必用 `-1`。

**名字前缀与拼写敏感**（查表实测）：`AttributeModifer_CryoBeam_02.._10`（拼写就是 `Modifer`，少一个 i）、
`AttributeModifier_IronCurtain`、`AttributeModifier_CryoSpray`、`AttributeMod_MAP_ObjectsFrozen` **存在**；
`AttributeModifier_MAP_OBJECTSFROZEN`、`_Frozen`、`_PermanentFrozen`、`_CryoFrozenArmor` 等**不存在**。

**`MAP_` 系列**（社区地编提供，可直接叠加在选中单位，走同一条施加链，无需召唤）：

| modifier | 哈希 | 效果 |
|---|---|---|
| `AttributeModifier_MAP_ARMOR_Up` | `0x505EBD44` | 减弱护甲 —— 单发 67.5 → 736（×10.9，有下限） |
| `AttributeModifier_MAP_HEALTH_MULT_Down` | `0xAC47C5FF` | 血量上限 ×0.9/层（线性可叠） |
| `AttributeModifier_MAP_SPEED_Down` | `0x46C6A82B` | 减速（"定身"的平滑版） |
| `AttributeMod_MAP_ObjectsFrozen` | `0xCDFDC01C` | 实心冰块模型（纯视觉） |

**状态字只作判据，不是开关**：冷冻 `Thing+0x98 = 0x4000`；铁幕 `Thing+0x98 = 0x10080` 且 `+0xD4 = 0x2000`。
已实测证伪「改状态位就能冻 / 解冻」—— 引擎判定在它内部的 modifier 列表里，必须走引擎函数。
两个函数都**不改 `Body`**（各扫 `0..0x800` 零变化）；`Body = [Thing+0x33C]`。

**`duration = -1` 的两个坑**：`MAP_` 系列约 12 秒就过期，一律给明确帧数；
引擎 crate 内部用 `-1` 却表现为不过期 —— 该矛盾未复核，使用时按显式帧数处理。

**社区口径**（语雀 `ra3mapwiki`《LuaAPI-LuaBridge》）：`ObjectLoadAttributeModifier(unit, name, [frameCnt])` /
`ObjectUnloadAttributeModifier(unit, name)` —— 正是上面这两个引擎函数。

**易碎当前实现**：`US_BRITTLE` = `ARMOR_Up` + `HEALTH_MULT_Down` 叠加（见 §二 状态表）。

**工具**：`ra3-copilot/tools/modifier_apply.py`（`--list` 挑目标 / `--dry` 只查表 / `--remove` 解除）。
