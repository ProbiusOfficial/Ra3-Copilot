# RA3 修改器「局内渲染」解决方案

---

## 一、结论先行

**局内渲染 = 用 MinHook 在游戏进程内 inline-hook d3d9 的 `Present` / `EndScene` 函数，
用「游戏自己的 device + 游戏自己的窗口」渲染 ImGui。**

**每帧逻辑的主驱动是 `BeginScene`**（一帧渲染开始，游戏逻辑已算完），**绘制的主驱动是 `EndScene`**
（放行游戏自己的 `EndScene` 之后再画，`ImGui_ImplDX9_RenderDrawData` 自己会 `BeginScene/EndScene` 一遍）。
`Present` 与 `SwapChain::Present` 只在 `BeginScene` 计数为 0 时兜底，避免一帧跑两遍。
`Reset` 期间置 `g_telemDeviceLost`，Tick 与绘制一律跳过（进对局的加载阶段就会 Reset）。

> 为什么不用 `Present`：实测某台机器上一整局 `IDirect3DDevice9::Present` 只中过一次，
> 而 `EndScene` / `BeginScene` 每帧必调（80 秒 2600 余次），挂在 Present 上的后果是面板画不出、
> 功能快捷键不生效、变更端点全超时、`/unload` 永不执行。
>
> **真因不是「Steam 版」**：那台机器上装着 RivaTuner Statistics Server（`RTSSHooks.dll`），
> 帧率 OSD 改写了呈现链，`d3d9.dll` 自身的 `Present` 因此几乎不被调到。`GET /env` 的
> 「非系统模块」一节能直接看到这类 OSD / 叠加层 —— 所以呈现路径要按机器采，不能按游戏版本推断。
> 「BeginScene / EndScene 每帧必调」才是稳的，渲染挂它们。
> 判据见 `/render`：`present` 恒 1 而 `endscene` 在涨，就是这条。

关键是**怎么拿到要 hook 的函数地址**——正确做法是：

1. 自己建一个 dummy 窗口（`RegisterClassExW` + `CreateWindowExW`）
2. `Direct3DCreate9(D3D_SDK_VERSION)` → `IDirect3D9::CreateDevice`（三种顶点处理 flag `0x40/0x80/0x20` 各试一次）
3. 从 dummy device 读 `vtable[16]=Reset / vtable[17]=Present / vtable[42]=EndScene` 的**函数地址**
   （这些地址落在 `d3d9.dll` 里，**被游戏自己的 device 共用**）
4. `MH_CreateHook(函数地址, 本体的 detour, &原函数)` → `MH_EnableHook`
5. 销毁 dummy 窗口/设备

> **为什么必须 hook「函数地址」而不是「vtable 数组项」**：
> 改 vtable 数组只作用于那张数组，而游戏自己的 device 用的是**另一张**
> → 改了对游戏毫无影响（症状：`d3dHooked=1` 但 `Present/EndScene` 计数恒 0）。
> 而 hook **函数本身**（同一份 `d3d9.dll` 代码）→ 任何 device 调用它都会命中。


**产物静态核对：**

| 项 | 结论 |
|---|---|
| d3d9 依赖 | **无静态导入**；`GetModuleHandleA("d3d9.dll")` + `GetProcAddress` 取 `Direct3DCreate9` / `Direct3DCreate9Ex`，vtable 走手读 |
| 关键字符串 | `MH_Initialize` / `MH_CreateHook` / `MH_EnableHook` → 用 MinHook 做 inline hook |
| dummy 窗口类名 | `ra3copilot_overlay_dummy`（宽字符） |
| 兜底窗口类名 | `Command & Conquer(tm) Red Alert(tm) 3`（FindWindowW 用） |
| dummy 生命周期 | `Release()` + `DestroyWindow()`（**hook 完就拆，不残留**） |
| 设备/窗口变更 | 有 `D3D device/hwnd changed — reinit ImGui` / `Reset — ImGui torn down` 处理 |

**为什么这样能工作**：`d3d9.dll` 里 `Present`/`EndScene` 是**同一份函数代码**，被游戏自己的 device 共用；
inline-hook 函数本身后，任何 device 调用它都会命中。

## 三、ra3-copilot 的实现

渲染部分在 `ra3-copilot/src/overlay.cpp`：

- `InstallRenderHooks()`：建 dummy 窗口 + dummy D3D9 device → 从 device 读 d3d9 vtable 取 `Reset`/`Present`/`EndScene` 的函数地址 → 销毁 dummy
- `HookFunction()`：把拿到的**函数地址**交给 `MH_CreateHook`（去重：同一地址只挂一次）
- `HookDeviceVtable()`：挂 `vt[16]=Reset` / `vt[17]=Present` / `vt[42]=EndScene` / `vt[44]=SetTransform`，并经 `GetSwapChain(0)` 挂 `SwapChain::Present`(`vt[3]`)
- 窗口来源：`GetCreationParameters().hFocusWindow` → `FindWindowW(RA3 类名)` → `EnumWindows` → `GetForegroundWindow`

**依赖：`third_party/minhook-1.3.3`（BSD-2，静态编入 DLL）。**
`build.bat` 独立编译 MinHook 到 `obj_mh\`，避免 MinHook 的 `hook.c` 与本项目 `hook.cpp` 都生成 `hook.obj` 冲突。

**渲染时机：**
- `Present` detour 内：首帧 `EnsureImGui(dev)`（用游戏 device + 窗口，并子类化 WndProc），菜单可见时 `RenderOverlay(dev)`，再调原 `Present`
- `EndScene` detour：仅计数
- `Reset` detour：`ImGui_ImplDX9_InvalidateDeviceObjects()` → 原 `Reset` → `CreateDeviceObjects()`
- `SwapChain::Present` detour：`GetDevice` → 同样渲染（覆盖个别环境只走 swapchain 的情况）

**依赖表：** PE32 i386 · `USER32/KERNEL32/SHELL32/IMM32/WS2_32`（**无 d3d9.dll 静态依赖**，vtable 走手读）。
关键字符串 `hooks armed` / `MH_Initialize failed` / 宽串 `ra3copilot_overlay_dummy` / `Command & Conquer(tm) Red Alert(tm) 3`。

## 四、实测步骤

1. 启动游戏并进入对局（遭遇战/战役均可）
2. 双击 `ra3-copilot\deploy.bat`（自提权 → 注入 x86 → 诊断）
3. 游戏内按呼出键（默认 `INSERT`，可在启动器里改）显示/隐藏菜单，面板正常响应点击与拖拽
4. **判据（在「设置 → 诊断」看）**：
   - `d3d9 函数已 hook: 5 个`（Reset/Present/EndScene/SwapPresent/SetTransform）
   - `渲染: EndScene=… Present=…` **持续增长**
   - 菜单**画在游戏画面里**（不是独立窗口）、**切出游戏窗口不静音**、**鼠标可点**

若 `EndScene/Present` 仍恒 0（理论上不应发生）：
- 优先怀疑游戏 device 用的 d3d9 函数与 dummy 的不同 → 扩展 flag 组合 / 直接 hook 游戏 device
- 用 `deploy.bat` 输出的 `tools\inject_probe_result.txt` 看诊断，并抓 `OutputDebugStringA` 日志（可用 DebugView）

## 五、约束与注意

- **版本绑定**：游戏 v1.12.3444.25830（功能 hook AOB fail-closed）
- `Present` 可能被**多设备/多线程**调用 → 只在 `dev == g_ov.device`（首次见到的游戏 device）时渲染，避免重复绘制
- 首次 `Present` 命中时才初始化 ImGui → 若菜单默认隐藏，仍需先跑一两帧 —— 初始化与显隐无关
- 输入用 `GetAsyncKeyState` 轮询 + `WndProc` 子类化双通道（`WS_EX` 不抢焦点）
