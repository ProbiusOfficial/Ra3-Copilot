# RA3 修改器「局内渲染」解决方案

> 2026-10-14 · 探宝 × 晨曦
> 且**不抢焦点、不让战场静音、不影响游戏运行**。

---

## 一、结论先行

**局内渲染 = 用 MinHook 在游戏进程内 inline-hook d3d9 的 `Present` / `EndScene` 函数，
在 `Present` 里用「游戏自己的 device + 游戏自己的窗口」渲染 ImGui，然后调用原函数。**

关键是**怎么拿到要 hook 的函数地址**——正确做法是：

1. 自己建一个 dummy 窗口（`RegisterClassExW` + `CreateWindowExW`）
2. `Direct3DCreate9(D3D_SDK_VERSION)` → `IDirect3D9::CreateDevice`（三种顶点处理 flag `0x40/0x80/0x20` 各试一次）
3. 从 dummy device 读 `vtable[16]=Reset / vtable[17]=Present / vtable[42]=EndScene` 的**函数地址**
   （这些地址落在 `d3d9.dll` 里，**被游戏自己的 device 共用**）
4. `MH_CreateHook(函数地址, 我们的 detour, &原函数)` → `MH_EnableHook`
5. 销毁 dummy 窗口/设备

> **为什么必须 hook「函数地址」而不是「vtable 数组项」**：
> 我上一版（v0.7）改的是 dummy device 的 vtable 数组 → 游戏自己的 device 用的是**另一张数组**
> → 改了对游戏毫无影响（症状：`d3dHooked=1` 但 `Present/EndScene` 计数恒 0）。
> 而 hook **函数本身**（同一份 d3d9.dll 代码）→ 任何 device 调用它都会命中。

**反汇编 `外部DLL`（静态核对）：**

| 项 | 结论 |
|---|---|
| d3d9 静态导入 | **只有 `Direct3DCreate9`** → 不依赖 d3d9 其它导出，vtable 走手读 |
| 关键字符串 | `MH_Initialize failed: %d` / `MH_CreateHook Present failed: %d` / `MH_EnableHook failed: %d` / `hook thread started (MinHook inline)` → **用的就是 MinHook** |
| dummy 窗口类名 | `ra3_overlay_d3d9_dummy`（宽字符） |
| 兜底窗口类名 | `Command & Conquer(tm) Red Alert(tm) 3`（FindWindowW 用） |
| `0x100016a0` 段 | `GetModuleHandleW("d3d9.dll")` 轮询等待 → `RegisterClassExW` → `CreateWindowExW(style=0x0CF0000)` |
| `0x10001770` 段 | `Direct3DCreate9(0x20)` → 循环 `{0x40,0x80,0x20}` 调 `IDirect3D9::CreateDevice`（`call [vtbl+0x40]`） |
| `0x100019a0` | `HookDeviceVtable(dev)`：读 `[dev vtable+0x40/0x44/0xa8]`(=`Reset/Present/EndScene`) → MinHook 挂载；再 `GetSwapChain` 挂 `SwapChain::Present` |
| `0x100017cc` | dummy 用完即 `Release()` + `DestroyWindow()`（**hook 完就拆，不残留**） |
| `0x100012c0` Present detour | `lock inc [计数器]` → `push [ebp+8]`(游戏 device) → `RenderOverlay(dev)` → **再**调原 `Present`（`ret 0x14`） |
| `0x10001de0` 取窗口 | `dev->GetCreationParameters(&cp)` → `cp.hFocusWindow`（+8）；失败 → `FindWindowW(类名)` → `GetForegroundWindow()` |
| `0x10001ef2` | `SetWindowLongW(hwnd, GWLP_WNDPROC=-4, OverlayWndProc)` → 子类化游戏窗口（喂 ImGui 输入 + 输入法） |
| 设备/窗口变更 | 有 `D3D device/hwnd changed — reinit ImGui` / `Reset — ImGui torn down` 处理 |


- `config.txt` 有 `CORONA_ENABLE_UI:1` + `luaPluginData` → 它是**日冕官方 Lua/UI 插件宿主**，
  摄像机/时间暂停/光照等功能走**游戏自带 UI 框架**
- **三个 DLL 均无任何 d3d9/Present/Device 导入** → **不 hook D3D，另一条路线**
- 结论：**它是「游戏内插件」范例（证明日冕里能正常渲染），但架构不适合修改器**（要改游戏脚本/UI 框架，重且受限）。

## 三、trainer-v2 的改动（v0.7 → v0.8）

**`src/overlay.cpp` 全面重写渲染部分：**

|---|---|
| `ScanAndHookDevices()` 扫游戏 `.data` 找 device 指针 | **删除**（不再扫内存） |
| 改 `vtable[16/17/42]` 数组项 | **`MH_CreateHook` 挂 d3d9 函数地址** |
| `LooksLikeDeviceVtbl()` 纯内存判定 119 方法 | 不需要（dummy device 拿到的就是真函数） |
| 自建窗口 + 自建设备（更早的 v0.3~v0.6） | 无窗口，直接画在游戏帧内 |
| — | 新增 `InstallRenderHooks()` / `HookDeviceVtable()` / `HookFunction()` |
| — | 窗口来源 `GetCreationParameters().hFocusWindow` → `FindWindowW(RA3类名)` → `EnumWindows` → `GetForegroundWindow` |

**新增依赖：`third_party/minhook-1.3.3`（BSD-2，静态编入 DLL）。**
`build.bat` 增加独立 MinHook 编译步骤（`obj_mh\`），避免 MinHook 的 `hook.c` 与本项目 `hook.cpp` 都生成 `hook.obj` 冲突。

**渲染时机：**
- `Present` detour 内：首帧初始化 ImGui（用游戏 device + 窗口），菜单可见时 `RenderOverlay(dev)`，再调原 `Present`
- `EndScene` detour：仅计数
- `Reset` detour：`ImGui_ImplDX9_InvalidateDeviceObjects()` → 原 `Reset` → `CreateDeviceObjects()`
- `SwapChain::Present` detour：`GetDevice` → 同样渲染（覆盖个别环境只走 swapchain 的情况）

**构建校验：** `BUILD_OK` · PE32 i386 · 依赖表 `USER32/KERNEL32/SHELL32/IMM32`（**无 d3d9.dll 静态依赖**，与参考一致）· 644,608 B
关键字符串 `hooks armed` / `MH_Initialize failed` / 宽串 `ra3_overlay_d3d9_dummy` / `Command & Conquer(tm) Red Alert(tm) 3` 均在。

## 四、实测步骤（待探宝执行）

1. 启动游戏并进入对局（遭遇战/战役均可）
2. 双击 `trainer-v2\deploy.bat`（自提权 → 注入 x86 → 诊断）
3. 游戏内按 `INSERT` 显示/隐藏菜单；`F7` 加钱
4. **判据（在「状态」页看）**：
   - `d3d9 函数已 hook: 4 个左右`（Reset/Present/EndScene/SwapPresent）
   - `渲染: EndScene=… Present=…` **持续增长**
   - 菜单**画在游戏画面里**（不是独立窗口）、**切出游戏窗口不静音**、**鼠标可点**

若 `EndScene/Present` 仍恒 0（理论上不应发生）：
- 说明游戏 device 用的 d3d9 函数与 dummy 的不同 → 需要扩展 flag 组合 / 直接 hook 游戏 device
- 用 `deploy.bat` 输出的 `tools\inject_probe_result.txt` 看诊断，并抓 `OutputDebugStringA` 日志（可用 DebugView）

## 五、遗留 / 注意

- **版本绑定**：游戏 v1.12.3444.25830（功能钩子 AOB fail-closed）
- `Present` 可能被**多设备/多线程**调用 → 只在 `dev == g_ov.device`（首次见到的游戏 device）时渲染，避免重复绘制
- 首次 `Present` 命中时才初始化 ImGui → 若菜单默认隐藏，仍需先跑一两帧（已保证：初始化与显隐无关）
- 输入用 `GetAsyncKeyState` 轮询 + `WndProc` 子类化双通道（`WS_EX` 不抢焦点）
