功能一览

所有变更类操作都由游戏主线程（渲染线程）执行，并在「输出记录」里留痕；注入前对每个挂钩点做 AOB 字节级校验（fail-closed，不符绝不 patch）。

渲染 overlay

MinHook inline-hook d3d9 的 Present/EndScene，用 ImGui 直接画在游戏画面内。

  • 不抢焦点、切窗口不静音
  • 鼠标在面板内自动穿透

资源 resource

  • 加钱 / 设置资金（实时读取）
  • 电力满、科技点满、全科技
  • 快速建造、免费建造
  • 敌方无法建造

战斗 combat

  • 玩家无敌、选中单位弹药满
  • 超武就绪 / 禁用敌方超武
  • 危险等级干预、全图去迷雾
  • 秒杀模式

单位 unit

  • 选中单位变速 / 改血 / 收编 / 摧毁 / 满级
  • 召唤单位与基地车
  • 空投箱子（可周期自动）

调试接口 http

进程内 HTTP（127.0.0.1:17832），只读端点由 HTTP 线程直接应答。

  • /state /snapshot /read /peek
  • /summon /poke /call

脑机接口 mcp

把进程内能力包装成标准 MCP 工具，任意支持 MCP 的 AI 客户端都能读取战局并给玩家投放单位 / 箱子。

  • 默认总闸关闭，只读不受影响

架构

功能核（进程内内存 patch）+ 渲染层（inline-hook）+ 输入线程，三者协作。

injector.exe (x86) ──CreateRemoteThread(LoadLibraryW)──► ra3trainer.dll (in-game)
                                                              │
                     ┌────────────────────────────────────────┼──────────────────────────┐
                     ▼                                        ▼                          ▼
            features.cpp (功能核)                 overlay.cpp (渲染层)             输入线程
            ├ 表驱动 hooks（kHooks[]）              ① 造 dummy window + dummy D3D9 device
            │   名/RVA/AOB/壳/返回地址               ② 读 device vtable[16/17/42] = Reset/Present/EndScene 的函数地址
            │   push/ret 与 E9 detour               ③ MinHook inline-hook 这些函数(+SwapChain::Present)
            └ 壳（stubs.asm）→ 洞内动作              ④ 销毁 dummy
                （改内存 / 记录对象）                 ⑤ Present detour 里用「游戏 device + 游戏窗口」渲染 ImGui → 再调原 Present

功能核

表驱动：新增功能 = 表里加一行 + 写一个 MASM 壳 + UI 加勾选框。

壳代码

MASM 编进 DLL .text，靠 PE 重定位补全局地址、FF 25 间接跳回游戏（无 ±2GB 限制）。

地址自愈

符号解析器（AOB 特征码 + 结构推导）替代硬编码 RVA，换版本 / 换 mod 后可重新定位。

渲染原理

为什么是 inline-hook「函数本身」，而不是改 vtable 数组、也不是自建窗口。

正解

1. 自建 dummy 窗口 + dummy device
2. 读 vtable[16/17/42] 得到 Reset/Present/EndScene 的函数地址
   （这些地址落在 d3d9.dll 里，被游戏自己的 device 共用）
3. MH_CreateHook(函数地址, detour, &原函数) → MH_EnableHook
4. 销毁 dummy（hook 完就拆）

走过的弯路

做法结果
改 dummy device 的 vtable 数组游戏 device 用另一张表 → 计数恒 0
扫内存找游戏 device三次崩溃，误挂率高
自建置顶窗口独立窗口，抢焦点、切窗口静音

正确判据：hook 函数本身，任何 device 调用它都会命中。

快速上手

需要先启动游戏并进入对局；注入器必须与游戏同为 32 位。

① 启动游戏

通过启动器进入对局（遭遇战 / 战役均可）。

② 注入

运行 trainer-v2\deploy.bat（自动 UAC 提权 → 注入 → 打印诊断）。

③ 呼出菜单

游戏内按 INSERT 显示 / 隐藏菜单，F7 加钱。

注意：显示菜单时会抢焦点（RTS 失焦会暂停），这是有意的 —— 否则鼠标键盘无法操作 UI。

脑机接口（MCP）

把修改器的进程内接口包装成标准 MCP 工具，让 AI 客户端读战局、投放部队。

工具

工具说明
get_battle_state我方/敌方部队建筑数、资金、选中单位
search_units单位检索（中文名 / 模板名 / 哈希）
summon_unit召唤单位
drop_crate空投箱子
selected_action复制 / 增援 / 基地车 / 收编 / 摧毁 / 满级
toggle_feature电力/全科技/免费建造/去迷雾/无敌…

接入

{
  "mcpServers": {
    "ra3-copilot": {
      "command": "python",
      "args": ["<仓库>/trainer-v2/mcp/ra3_mcp.py"]
    }
  }
}

游戏内「脑机接口」面板点开总闸后，AI 才能执行变更类操作；只读始终可用。
